# MaxxGPT — Performance Analysis (วิเคราะห์ผลโฆษณา 6 หัวข้อ)

พา user จาก "อยากดูผลแอด" ไปจนได้ **สรุป + ตารางผลจริง** ของบัญชีโฆษณาที่ผูกไว้กับ MaxxGPT
แล้วอยู่ต่อเพื่อตอบคำถามเจาะลึกจากข้อมูลชุดเดียวกัน

Pick a report + a date range, run it, and show the numbers — then stay to answer follow-ups.

> ## 🔴 กฎเหล็ก 5 ข้อ (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error `The connector's server isn't
>    responding.` ที่**ดูเหมือน server พังทั้งที่ไม่ใช่** · เจอ error นี้ให้สงสัยวิธีเรียกของตัวเองก่อน
> 2. **ทุกหัวข้อเป็นงาน async** — ยิง tool ได้ `job_id` แล้วต้อง **poll `get_job` เองจนจบ** ตาม
>    `poll_hint.poll_after_seconds` · **ห้ามจบ turn คืนงานให้ user ระหว่างรอ**
> 3. **ห้ามเทข้อมูลดิบทั้งก้อนลงแชท** — คำนวณยอดรวมจากข้อมูลเต็ม แล้ว**ตัดเหลือ 10 แถวต่อระดับ**
>    เสมอ (ดู § 5) · ข้อมูลเต็มยังอยู่กับเราไว้ตอบคำถามต่อ
> 4. **ตัวเลขทุกตัวต้องมาจาก `data` จริงเท่านั้น** — คีย์ไหนไม่มีก็ตัดคอลัมน์นั้นทิ้ง
>    **ห้ามเดา ห้ามเติมค่าที่ระบบไม่ได้ส่งมา ห้ามคำนวณเมตริกใหม่ที่ปลายทางไม่ได้ให้**
> 5. **ห้ามสร้าง widget / ฟอร์ม HTML / การ์ด UI เด็ดขาด** — ห้ามเรียก tool แสดงวิชวลทุกตัว
>    (`visualize` · `show_widget` · `render-ui` · Artifact) และ**ห้ามเขียน HTML/ฟอร์มเอง**
>    ถามด้วย **tool `AskUserQuestion` (ปุ่มตัวเลือก)** เท่านั้น · เรียกไม่ได้จริง ๆ =
>    **ถามเป็นข้อความแบบเลขข้อ (1 / 2 / 3) แล้วหยุดรอ user ตอบ** ห้ามเดาเองแล้วยิงต่อ

> แต่ให้บอกหนึ่งบรรทัดตอนจบว่าโดเมนหลักคือ `https://mcp.maxxgpt.ai/mcp` และแนะนำให้ย้าย ·
> **บอกครั้งเดียวต่อ session พอ อย่าทวงซ้ำทุกรอบ**

ไม่มี connector นี้ = แจ้ง user พร้อม URL แล้วหยุด อย่าเดินหน้าด้วยการเดา ·
**ชื่อ tool ของแต่ละ user อาจไม่ตรงเป๊ะ** (เปลี่ยนชื่อเองได้) → จับคู่จาก *ความสามารถ* ไม่ใช่ชื่อเป๊ะ ๆ

> **บัญชีโฆษณา · เพจ (MaxxGPT V4)** — ไม่ส่งอะไร = tool ใช้บัญชี/เพจที่ user เลือกไว้ในเว็บ MaxxGPT · สกิลนี้ส่ง `ad_account_id` ที่ได้จากขั้น 0 ทุกครั้ง ·
> tool ที่ทำงานกับบัญชีโฆษณารับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ · `get_job` / `search_interest` / `suggest_interest` ไม่มีสอง argument นี้) ·
> id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
> user มีหลายบัญชีแล้วไม่ระบุ → ถามก่อนตามขั้น 0 (ห้ามเลือกให้เอง) แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (คำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง · ยกเว้น `get_job` · `get_dashboard_demographics` แนบตั้งแต่ MCP 1.23.2) · ส่ง `ad_account_id` ให้ tool ใด ต้องส่งค่าเดียวกันให้ `get_account_info` ด้วย และเรียก `get_account_info` ใหม่เมื่อเปลี่ยนบัญชี (สกุลเงิน/โซนเวลาเป็นของบัญชีนั้น)
>
> **ตั้งค่าบัญชี/เพจได้ที่หน้าเว็บ MaxxGPT เท่านั้น** — MCP เชื่อมต่อ Meta, ผูก, ถอด หรือเปลี่ยนบัญชี/เพจที่เลือกไว้ให้ไม่ได้ (`ad_account_id` / `page_id` ใช้แค่ครั้งนั้น ไม่เปลี่ยนค่าในเว็บ) · ยังไม่ผูกบัญชี · ผูกเกินโควตา · หรือ user ต้องการบัญชีที่ไม่อยู่ใน `list_ad_accounts` → บอกให้ไปทำในเว็บ MaxxGPT (เมนู ☰ → บัญชีโฆษณาและเพจ) แล้วค่อยกลับมาสั่งใหม่ · **ห้ามบอกว่าจะผูกหรือตั้งค่าให้**
>
> **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
> `reason: OVER_QUOTA` = ผูกบัญชีโฆษณาหรือเพจเกินโควตาแพ็กเกจ (`ad_account_quota.over_quota` / `page_quota.over_quota`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
> `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์ (tool ที่สกิลนี้ใช้ยังไม่มีตัวไหนตอบรหัสนี้) · `SUBSCRIPTION_EXPIRED` (403) = แพ็กเกจหมดอายุ → ให้ต่ออายุในเว็บ MaxxGPT (ล็อกอินใหม่ไม่ช่วย) · `NO_SESSION` / `USER_NOT_FOUND` (401) = connector ไม่รู้จักผู้ใช้ → ให้เชื่อมต่อ connector MaxxGPT ใหม่ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้

## 🔀 สกิลนี้เป็น "ทางเข้ารวม" — รู้หัวข้อแล้วให้ส่งต่อ

แต่ละหัวข้อมี**สกิลของตัวเอง**แล้ว (เนื้อหาละเอียดกว่า มีกับดักเฉพาะหัวข้อครบกว่า) ·
สกิลนี้มีไว้สำหรับตอนที่ **ยังไม่รู้ว่า user อยากดูหัวข้อไหน** เท่านั้น

| `topic` | สกิลรายหัวข้อที่ควรใช้แทน |
|---|---|
| `video` | `maxxgpt-analysis-video-ads` |
| `posteng` | `maxxgpt-analysis-post-engagement` |
| `message` | `maxxgpt-analysis-message` |
| `purchase_meta` | `maxxgpt-analysis-purchase-meta` |
| `purchase_cpas` | `maxxgpt-analysis-purchase-cpas` |
| `leads` | `maxxgpt-analysis-leads` |

**กติกา:**

- **รู้หัวข้อตั้งแต่ต้น** (user บอกมา / เดาจากบริบทได้ชัด) → **เรียกสกิลรายหัวข้อไปเลย ไม่ต้องเปิดเมนูของสกิลนี้**
- **user เพิ่งเลือกหัวข้อจากเมนูของสกิลนี้** → ส่งต่อให้สกิลรายหัวข้อพร้อมช่วงวันที่ที่ได้มา
  **ถ้าสกิลรายหัวข้อนั้นไม่ได้ติดตั้งอยู่ ให้ทำต่อเองในสกิลนี้ตามขั้น 2-5 ปกติ** (ยังทำได้ครบ)
- ทั้งสองทางให้ผลเหมือนกัน — **ห้ามทำสองรอบ ห้ามยิง tool ซ้ำ**

## ⚡ ทางลัด · มี `job_id` มาแล้ว = ข้ามไปวิเคราะห์เลย

**ถ้าข้อความของ user มี `job_id` ติดมา ให้ข้ามขั้น 1-2 ทั้งหมด** — ไม่ต้องถามอะไรเพิ่มเลือกหัวข้อ
**ไม่ต้องยิง `analysis_*` ใหม่** (ยิงใหม่ = เสียเวลา 1-5 นาที + เปลืองโควตา + อาจชน `JOB_ALREADY_RUNNING`)

**นับว่า "มี job_id" เมื่อ:** user พิมพ์/วางมาตรง ๆ (`job_id=…` · `[job_id=…]` · "ดูผลจากจ็อบ …" ·
วาง id ดิบ ๆ มาพร้อมบอกให้วิเคราะห์) · สกิลอื่นหรือเทิร์นก่อนหน้าส่งต่อมาให้ · งานตั้งเวลา/ระบบภายนอกแนบมา

```
job_id ที่ได้มา ──► get_job(job_id) ──► poll จน success ──► เช็คลายเซ็นว่าเป็นหัวข้อไหน ──► ตัด+แสดงผล
```

### ทำตามนี้

1. **`get_job(job_id)` ทันที** — `processing` ก็ poll ต่อตามขั้น 3 ปกติ
2. **`get_account_info`** ยังต้องเรียก (1 ครั้งต่อ session ต่อบัญชี) เพื่อเอา **สกุลเงิน + ชื่อบัญชี** ไปใส่หัวเรื่อง —
   แต่เรียกตอนไหนก็ได้ ไม่ต้องรอก่อน get_job
3. **หาว่าเป็นหัวข้อไหนจาก `function_name`** (ไม่มีค่านี้ค่อยดูรูปร่างของ `data` — ดูตารางข้างล่าง) แล้วใช้กติกาคอลัมน์/สรุปของหัวข้อนั้นใน § 5
   → เป็น 1 ใน 6 หัวข้อของสกิลนี้ = เดินต่อขั้น 4-5 ปกติ **บอก user ด้วยว่าอ่านได้ว่าเป็นหัวข้ออะไร**
   → **เป็นของสกิลอื่น** = ห้ามฝืนแปลง บอก user แล้วชี้สกิลที่ตรง
   → เดาไม่ออก = แสดงเท่าที่คีย์จริงมี + เขียนใน `note` ว่าไม่แน่ใจว่าเป็นหัวข้อไหน **ห้ามเดาเงียบ ๆ**
4. **ช่วงวันที่และบัญชีของ job: `get_job` ไม่ได้คืนมาด้วย** — 🔴 **ห้ามเดา ห้ามใส่ช่วงมั่ว ๆ ในหัวเรื่อง**
   · user บอกช่วงมาด้วย = ใช้ตามนั้น · ไม่บอก = เว้นช่วงวันที่ในหัวเรื่องไว้ แล้วเขียนในหมายเหตุว่า
   "ผลชุดนี้มาจาก job ที่ส่งมา — ระบบไม่ได้แนบช่วงวันที่มาด้วย" ·
   ชื่อบัญชีในหัวเรื่องคือบัญชีจาก `get_account_info` ตอนนี้ — เขียนในหมายเหตุด้วยว่า **ไม่ยืนยันว่า job นี้รันกับบัญชีนั้น**
5. `code: JOB_NOT_FOUND` = **job_id ผิด เป็นของ user คนอื่น หรือเป็น job_id จากระบบเดิมก่อน V4** (job ผูกกับ login) →
   บอกตรง ๆ แล้วเสนอรันใหม่ตามขั้น 1-2 ปกติ · **ห้าม poll ซ้ำ** (`poll_hint.poll_after_seconds` = 0)
6. `job_status: failed` = งานเก่าล้มไปแล้ว → อ่าน `data.error` ตามขั้น 3 ก่อนเสนอรันใหม่ · `data` ว่าง `{}` = ช่วงนั้นไม่มีข้อมูล ไม่ใช่ error ·
   `job_status: success` แต่ `data` เป็น `null` = ผลหมดอายุแล้ว (ระบบเก็บผล 7 วัน) → เสนอรันใหม่

**ดู `function_name` ก่อนเสมอ** — `get_job` คืนค่านี้มาด้วย และใช้ได้แม้ `data` เป็น `{}`

| `videoAdsAnalysis` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| `postEngagement` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| `messageAnalysis` | ทักแชท | `maxxgpt-analysis-message` |
| `leadAdsAnalysis` | ลีด | `maxxgpt-analysis-leads` |
| `purchaseAnalysisMETA` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| `purchaseAnalysisCPAS` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `resultOverAll` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |

**ไม่มี `function_name` ในคำตอบ** = ใช้ลายเซ็นใน `data` แทน:

| ลายเซ็นใน `data` | หัวข้อ | สกิลที่ควรใช้ |
|---|---|---|
| `Ad` เป็น **object** `{Close,Watch,Keep}` | Bottom Rank | `maxxgpt-rank-bottom-ads` |
| แถวมี `Score` + `CPC` · **ไม่มี `CPM`** และไม่มีคอลัมน์ผลลัพธ์ | Rising Stars | `maxxgpt-rank-rising-stars` |
| แถวมี `Score` + `Reach` + `Frequency` + `CPM` + `CPC` | Audience Growth | `maxxgpt-rank-audience-growth` |
| แถวมี `Score` + `CPM` · ไม่มี `Reach`/`CPC` (`Cost_per_*` `per` ตัวเล็ก มีเฉพาะเมตริก inbox / lead) | Top Rank | `maxxgpt-rank-top-ads` |
| แถวมี `Video_plays` + `Completion_Rate` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| แถวมี `Post_Engagement` + `post_engagement_rate` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| แถวมี `Inbox` + `MSS_VIEW` + `Cost_Per_Inbox` (`Per` ตัวใหญ่) | ทักแชท | `maxxgpt-analysis-message` |
| แถวมี `Lead` + `Cost_per_lead` | ลีด | `maxxgpt-analysis-leads` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **และ** มีคีย์ `Age`/`Gender` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **แต่ไม่มี** คีย์ `Age`/`Gender` และไม่มี `Score` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `data` มีคีย์ `OV` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |
| `data` มีบล็อก `CTR`/`CPM`/`FRQ` + `*_AD` | Ad Metric Benchmark (สเต็ป 2) | `maxxgpt-ad-metric-benchmark` |

⚠️ `purchase_meta` กับ `purchase_cpas` คอลัมน์เหมือนกันเป๊ะ ถ้าไม่มี `function_name` จะแยกได้แค่จากคีย์ `Age`/`Gender` —
**ถ้าไม่มั่นใจให้บอก user ตรง ๆ ว่าเดาว่าเป็นหัวข้อไหน แล้วให้ยืนยัน** อย่าเงียบแล้วเดา

## ผังการทำงาน · Flow

```
0  list_ad_accounts → get_account_info ──► รู้ชื่อบัญชี + สกุลเงิน + โซนเวลา
1  ถามเลือกหัวข้อ + ช่วงเวลา ด้วย AskUserQuestion  ◄── ข้ามได้ถ้า user บอกมาแล้ว
2  ยิง analysis_<หัวข้อ>(date_start, date_end)  ──► { job_id, code }
3  วนเรียก get_job จนกว่า job_status = success   ◄── ตาม poll_hint ห้ามจบ turn
4  ตัดข้อมูล + คำนวณยอดรวม
5  พิมพ์สรุป + ตาราง markdown             ──►  อยู่ต่อเพื่อตอบคำถามจากข้อมูลชุดเดิม
```

### ขั้น 0 · รู้ก่อนว่าบัญชีไหน

**0.1 · `list_ad_accounts`** (ครั้งแรกของ session · อ่านจากฐานข้อมูล MaxxGPT ไม่ยิง Meta) — ได้ทุกบัญชีที่ user ผูกไว้ (`ad_accounts[]` · `is_active` = ตัวที่เลือกไว้ในเว็บ) + `active_ad_account_id` + `ad_account_quota`

| เจอแบบนี้ | ทำอย่างนี้ |
|---|---|
| `ad_accounts` ว่าง หรือ `ad_account_quota.over_quota: true` | บอก user ให้ไปตั้งที่เว็บ MaxxGPT (ยังไม่ผูก = เชื่อมต่อ Meta แล้วเลือกบัญชี · เกินโควตา = เลือกบัญชีที่จะเก็บ) แล้ว**หยุด** — MCP ทำแทนไม่ได้ |
| user บอกบัญชีมาแล้ว (ชื่อหรือเลข) | จับคู่กับรายการ · ไม่เจอ = บอกว่าบัญชีนั้นยังไม่ได้ผูกใน MaxxGPT ให้ไปผูกที่เว็บก่อน · **ห้ามใช้บัญชีอื่นแทนเงียบ ๆ** |
| มีบัญชีเดียว | ใช้บัญชีนั้น ไม่ต้องถาม |
| หลายบัญชี และ user ไม่ได้ระบุ | ถามด้วย `AskUserQuestion` (รวมกับคำถามของขั้น 1 ได้) · ตัวเลือก = ชื่อบัญชี + `act_…` · ตัวที่ `is_active` อยู่บนสุด ติดว่า "(ที่เลือกไว้ในเว็บ)" · เกิน 4 บัญชี = ใส่ 3 ตัวแรก ที่เหลือให้พิมพ์ใน Other · ไม่มี `AskUserQuestion` = พิมพ์รายการเป็นเลขข้อให้ตอบ |
| connector ไม่มี `list_ad_accounts` (MaxxGPT รุ่นก่อน V4) | ข้าม 0.1 ใช้บัญชีที่เลือกไว้ในเว็บ ไม่ส่ง `ad_account_id` |

บัญชีที่ได้คือ `ad_account_id` ของงานนี้ — **ส่งค่าเดียวกันให้ทุก tool ของ MaxxGPT ในสกิลนี้** (ยกเว้น `get_job`) · ไม่เปลี่ยนบัญชีที่เลือกไว้ในเว็บ · user ขอเปลี่ยนบัญชีกลางทาง = ทำ 0.2 ใหม่ด้วยบัญชีนั้น

**0.2 · `get_account_info`** พร้อม `ad_account_id` จาก 0.1 — เรียก**หนึ่งครั้งต่อ session ต่อบัญชี** เก็บ ชื่อบัญชี / `act_…` / สกุลเงิน / โซนเวลา ไว้ใช้ทุกขั้น

tool คืน `{ success, ad_account, page }` — ที่ต้องหยิบไปใช้:

| คีย์ใน `ad_account` | เอาไปใช้ตรงไหน | หมายเหตุ |
|---|---|---|
| `name` | ชื่อบัญชีในหัวเรื่อง | ชื่อบัญชีโฆษณา |
| `id` | วงเล็บต่อท้ายชื่อบัญชี | มี prefix `act_` มาแล้ว (`account_id` คือตัวไม่มี prefix) |
| `currency` | หน่วยเงินต่อท้ายตัวเลขเงินในตาราง | เช่น `THB` — `null` ได้ |
| `timezone_name` | ใช้คำนวณ "วันนี้" ตอนแปลงช่วงเวลา | เช่น `Asia/Bangkok` |
| `account_status` | เตือนไว้ในหมายเหตุถ้าบัญชีมีปัญหา | **เป็นตัวเลข ไม่ใช่ข้อความ** — `1` = ใช้งานได้ · ค่าอื่น (`2`,`3`,`101`,…) = บัญชีมีปัญหา · `null` = MaxxGPT ยังไม่เคยอ่านค่านี้จาก Meta (ไม่ใช่บัญชีมีปัญหา) |
| `synced_at` | รู้ว่า `account_status` / `timezone_name` เก่าแค่ไหน | สองค่านั้นคือค่าที่ MaxxGPT อ่านจาก Meta ล่าสุด ณ เวลานี้ ไม่ใช่ค่าสด — `null` ได้ |

- โซนเวลาใช้คำนวณ **"วันนี้"** ตอนแปลงคำพูดเป็นช่วงวันที่ — หาไม่เจอให้ใช้ `Asia/Bangkok`
- สกุลเงินใช้ต่อท้ายตัวเลขเงินทุกตัว — หาไม่เจอให้เว้นว่าง **ห้ามเดาว่าเป็น THB**
- บัญชีที่ `account_status` ไม่ใช่ `1` ยังดูผลย้อนหลังได้ ทำต่อได้ปกติ (เขียนเตือนไว้ในหมายเหตุ)

### ขั้น 1 · เลือกหัวข้อ + ช่วงเวลา

**ถ้า user บอกมาครบแล้ว ไม่ต้องถามอะไรอีก** — บอกหนึ่งบรรทัดว่าใช้หัวข้อ/ช่วงไหน แล้วยิงต่อ

| user พูดมาแบบ | ทำอะไร |
|---|---|
| บอกครบ ("ดูผลวิดีโอเดือนที่แล้ว") | ไม่ต้องถาม → ยิงเลย + บอกหนึ่งบรรทัดว่าใช้ช่วง `YYYY-MM-DD → YYYY-MM-DD` |
| บอกแต่หัวข้อ ("ดูผลแชท") + **เคยรู้ช่วงเวลาแล้วใน session นี้** | ใช้ช่วงเดิมต่อ ยิงเลย + บอกว่าใช้ช่วงเดิม |
| บอกแต่หัวข้อ และยังไม่เคยรู้ช่วงเวลา | ถามเฉพาะช่วงเวลา (หัวข้อรู้แล้ว อย่าถามซ้ำ) |
| บอกแต่ช่วงเวลา | ถามเฉพาะหัวข้อ (ช่วงเวลารู้แล้ว อย่าถามซ้ำ) |
| ไม่บอกอะไรเลย | ถามหัวข้อ + ช่วงเวลาด้วย `AskUserQuestion` ครั้งเดียว |

**ห้ามถามช่วงเวลาซ้ำ** ถ้า session นี้เคยได้ช่วงเวลามาแล้ว — ใช้ค่าเดิมต่อ แล้วบอกว่ากำลังใช้ช่วงไหน
(user เปลี่ยนทีหลังได้โดยบอกมาในแชท (ไม่ต้องถามใหม่ด้วยปุ่ม))

**ถามยังไง — ใช้ tool `AskUserQuestion` (ปุ่มตัวเลือก) เสมอ · ห้ามสร้าง widget/ฟอร์ม HTML · ห้ามพิมพ์คำถามเปล่า ๆ:**
สเปกคำถาม/ตัวเลือกอยู่ใน [references/output-format.md](references/output-format.md) § ถาม — เมนู 6 หัวข้อ (ถาม 2 ชั้น เพราะปุ่มใส่ได้ทีละ 4) + ช่วงเวลา
**ถามทุกอย่างที่ยังไม่รู้ในการเรียกครั้งเดียว** · ที่รู้แล้วห้ามถามซ้ำ

| หัวข้อ (`topic`) | tool | พารามิเตอร์ |
|---|---|---|
| `video` | `analysis_video_ads` | `date_start`, `date_end` |
| `posteng` | `analysis_post_engagement` | `date_start`, `date_end` |

ผลที่ได้คือ `{ job_id, code }` — **`code` มี 2 แบบที่ต้องแยก:**

| `code` | หมายถึง | ทำอะไรต่อ |
|---|---|---|
| `JOB_CREATED` | เริ่มงานใหม่แล้ว | poll ตามปกติ |
| `JOB_ALREADY_RUNNING` | **มีงานหัวข้อเดียวกันค้างอยู่ — `job_id` ที่ได้เป็นของงานเก่า** | poll ต่อได้ แต่ **ผลที่ออกมาเป็นของช่วงวันที่ที่สั่งไว้รอบก่อน ไม่ใช่ที่เพิ่งขอ** → บอก user ตรง ๆ + เขียนข้อความนี้ไว้ในหมายเหตุใต้ตาราง แล้วเสนอให้รันใหม่หลังงานเก่าจบ |

> 1 user มีงานของ **หัวข้อเดียวกัน** ได้ทีละ 1 งาน (คนละหัวข้อรันพร้อมกันได้ แต่เรายังยิง tool ทีละตัวอยู่ดี)

### ขั้น 3 · รอผล (poll)

```
get_job(job_id)  →  { job_status, function_name, progression, data, poll_hint }
```

- `processing` → รอ `poll_hint.poll_after_seconds` วินาที **พิมพ์บรรทัดสั้น ๆ ให้ user เห็นว่ายังทำงานอยู่**
  (เช่น "ยังประมวลผลอยู่ ~40% — เช็คอีกครั้งใน 15 วิ") แล้ว poll ต่อ **ห้ามจบ turn**
- `success` → อ่าน `data` · **`data` อาจมาเป็นสตริง JSON → parse ก่อนใช้**
- `failed` + `data = {"error":"time_out"}` → **งานเกินเพดานเวลา 5 นาที** ห้ามยิงซ้ำทันที:
  บอก user ว่าช่วงที่ขอหนักเกินไป แล้วเสนอ **ย่นช่วงวัน** (30 วัน → 7-14 วัน) ก่อนรันใหม่
- `poll_hint.poll_after_seconds = 0` = หยุด อย่า poll ต่อ
- `failed` ที่ `data.error` เป็นค่าอื่น → **อย่ารันซ้ำเฉย ๆ** ให้อ่านรหัสก่อน: `META_TOKEN_INVALID` = การเชื่อมต่อ Meta หมดอายุ/ถูกยกเลิก →
  ให้ user ต่อ Meta ใหม่ในเว็บ MaxxGPT (รันซ้ำไม่ช่วย) · `META_RATE_LIMITED` = Meta จำกัดคำขอชั่วคราว รอ 2-3 นาทีแล้วค่อยรันใหม่ ·
  `META_PERMISSION_DENIED` = บัญชีที่ต่อไว้ไม่มีสิทธิ์ในบัญชีโฆษณานี้ · รหัสอื่น (`META_ERROR` ฯลฯ) = บอก `data.message` แล้วเสนอรันใหม่
- tool ตอบ error แทน `job_id` → อ่าน `code` ตามกล่อง "รหัสที่ต้องรู้จัก (V4)" ข้างบน · วันที่ผิดรูป (ไม่ใช่ `YYYY-MM-DD`) ถูกปฏิเสธตั้งแต่ตอนเรียก tool
- ได้ข้อความ `Rate limit reached …` → รอตามจำนวนวินาทีที่ข้อความบอก แล้วทำต่อเอง **ห้ามจบ turn** (เริ่มงานได้ 20 ครั้ง/ชั่วโมงต่อ tool)

อ่าน [references/output-shape.md](references/output-shape.md) เพื่อรู้ว่าหัวข้อนั้นมีคีย์/คอลัมน์อะไร
แล้วพิมพ์เป็นข้อความ + ตาราง markdown ตาม [references/output-format.md](references/output-format.md) § ตอบ

## § 5 · กติกาตัดข้อมูลก่อนพิมพ์ตาราง (ห้ามข้าม)

| ส่วน | ใส่อะไร |
|---|---|
| สรุปรวม | **คำนวณจากข้อมูลเต็ม** — รวมจากแถวระดับ **Campaign** (ไม่ใช่ Ad เพื่อไม่ให้นับซ้ำ) |
| ตาราง | 3 ตาราง: แคมเปญ / Ad set / โฆษณา · **แต่ละระดับเอาแค่ 10 แถวแรก** เรียงจากเมตริกหลักมาก→น้อย · ถ้าตัดออก ให้เขียนใต้ตารางว่า "แสดง 10 จากทั้งหมด N" |
| คอลัมน์ | 4-6 คอลัมน์พอ: ชื่อ · Spend · เมตริกหลัก · ต้นทุนต่อผล · CTR — **ห้ามยัดทุกคอลัมน์ที่มี** |
| breakdown | breakdown ใส่ **ครบทุกแถว** ได้ (มีไม่กี่แถว): อายุ · เพศ · อุปกรณ์ · แพลตฟอร์ม · ตำแหน่ง |
| ปิดท้าย | บรรทัดชวนถามต่อ (ดูด้านล่าง) |

**ยอดรวมคำนวณยังไงถึงจะถูก:**

- `Spend รวม` = ผลบวก `Spend` ของทุกแถว Campaign
- `ผลลัพธ์รวม` = ผลบวกเมตริกหลักของทุกแถว Campaign
- **ต้นทุนต่อผลรวม = `Spend รวม ÷ ผลลัพธ์รวม`** — **ห้ามเอาต้นทุนต่อผลของแต่ละแถวมาเฉลี่ย** (ได้เลขผิด)
- `CTR รวม` ก็เช่นกัน: `Clicks รวม × 100 ÷ Impression รวม` ไม่ใช่ค่าเฉลี่ยของ `CTR` รายแถว

**สรุปรวม 4 ช่อง ต่อหัวข้อ (พิมพ์เป็นตารางเดียว):**

| หัวข้อ | ใบ 1 | ใบ 2 | ใบ 3 | ใบ 4 |
|---|---|---|---|---|
| `video` | ยอดใช้จ่าย | ยอดเล่นวิดีโอ (`Video_plays`) | อัตราดูจบ (`Completion_Rate`) | CTR |
| `posteng` | ยอดใช้จ่าย | เอนเกจ (`Post_Engagement`) | ต้นทุน/เอนเกจ | CTR |
| `message` | ยอดใช้จ่าย | แชท (`Inbox`) | ต้นทุน/แชท | CTR |
| `purchase_meta` · `purchase_cpas` | ยอดใช้จ่าย | ยอดซื้อ (`Purchase`) | มูลค่า (`Purchase_Value`) | ROAS |
| `leads` | ยอดใช้จ่าย | ลีด (`Lead`) | ต้นทุน/ลีด | CTR |

หัวข้อที่มี `Recomment` → เพิ่มช่องที่ 5 ในสรุปรวม **"โฆษณาที่ระบบแนะนำ"** = `Recomment.Ad.Normal.ad_name`
(`sub` ใส่ตัวเลขประกอบ เช่น Score/ผลลัพธ์) · ไม่มีข้อมูลก็ข้ามใบนี้ไป

**บรรทัดชวนถามต่อ (พิมพ์ปิดท้ายเสมอ):**

```
ถามต่อได้: ขอตารางเต็ม (ทุกแถว) · เลือกหัวข้ออื่น · เปลี่ยนช่วงเวลา
```

**หมายเหตุ (bullet `⚠️` ใต้ตาราง) ใส่เมื่อ:** ช่วงที่ขอรวมวันนี้ (ข้อมูลยังไม่ครบวัน) · ผลว่าง ·
ผลมาจาก job เก่า (`JOB_ALREADY_RUNNING`) · บัญชีไม่ ACTIVE

**ผลว่าง (`data` = `{}` หรือทุกคีย์เป็น array ว่าง):** ยังพิมพ์หัวเรื่องตามปกติ แต่บอกตรง ๆ ว่าไม่มีข้อมูล
แล้วอธิบายเหตุผลแบบภาษาคน ("ช่วงนี้ไม่มีแคมเปญที่เข้าเกณฑ์ของรายงานนี้") ·
เสนอ 2 ทาง: ลองช่วงเวลาอื่น หรือลองหัวข้อที่ตรงกับ objective ที่บัญชียิงอยู่จริง

## หลังแสดงผล — อยู่ต่อเพื่อตอบคำถาม

หลังพิมพ์ตารางแล้ว **เขียนสรุปสั้น ๆ 2-4 บรรทัด** (อะไรเด่น อะไรน่าห่วง) แล้วบอกว่าถามต่อได้
— **อย่าเทข้อมูลดิบซ้ำลงในแชท**

ตอบคำถามต่อจาก **ข้อมูลชุดเดิมที่ดึงมาแล้ว** ห้ามยิง tool ซ้ำ เว้นแต่:

| user ขอ | ทำอะไร |
|---|---|
| ตัวเลข/อันดับ/เจาะแถวใดแถวหนึ่ง/ตารางเต็ม | ตอบจากข้อมูลเดิม **ไม่ต้องยิงใหม่** |
| เปลี่ยนช่วงเวลา | ยิงหัวข้อเดิมด้วยช่วงใหม่ |
| เปลี่ยนหัวข้อ | ยิงหัวข้อใหม่ (จำช่วงเวลาเดิมไว้ ไม่ต้องถามซ้ำ) |
| "ตัวไหนควรปิด / ตัวไหนควรดันงบ" | ตอบจากข้อมูลเดิมได้ แต่บอกด้วยว่ามีสกิลจัดอันดับ (Top/Bottom Rank, Rising Stars) แยกต่างหาก |

ขอตารางเต็ม = พิมพ์ทุกแถวเป็น markdown ในแชท · ถ้ายาวมากให้แบ่งตามระดับ
แล้วถามว่าจะดูระดับไหนก่อน

## ข้อควรระวังเรื่องตัวเลข

- **สตางค์/หน่วยเงิน**: ค่าที่ปลายทางส่งมาเป็นหน่วยเงินปกติแล้ว (ไม่ใช่สตางค์) — ใช้ตามที่ได้มา ห้ามคูณ/หาร 100
- **`CTR` เป็นเปอร์เซ็นต์อยู่แล้ว** (เช่น `1.84` = 1.84%) → พิมพ์ต่อท้ายด้วย `%` **ห้ามคูณ 100 ซ้ำ**
- **`Completion_Rate` / `Inbox_Rate` / `post_engagement_rate`** ก็เป็นเปอร์เซ็นต์เช่นกัน ·
  **`Inbox_Rate` = `Inbox ÷ MSS_VIEW × 100` (หารด้วยยอดเปิดดูข้อความ) → เกิน 100% ได้ปกติ ไม่ใช่ค่าผิด**
- 🔴 **ต้นทุนต่อผล = `0` แปลว่า "ไม่มีผลลัพธ์" ไม่ใช่ "ถูก"** — แถวที่เมตริกหลัก = 0 ได้ `Cost_*` เป็น `0`
  → **ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่าตัวไหนถูกสุดเสมอ**
- **`ROAS` เป็นเท่า ไม่ใช่ %** → หัวคอลัมน์เขียนว่า "ROAS (เท่า)"
- แถวที่เมตริกหลักเป็น 0 ยังนับรวมใน `Spend` — อย่าตัดออกจากยอดรวม (ตัดได้แค่ตอนเลือก 10 แถวมาโชว์)
