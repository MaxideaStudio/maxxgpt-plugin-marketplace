# MaxxGPT — Rising Stars (โฆษณาดาวรุ่ง)

พา user จาก "มีตัวไหนควรเพิ่มงบไหม" ไปจนได้ **รายการดาวรุ่งจริง** ของบัญชีที่ผูกกับ MaxxGPT
แล้วอยู่ต่อเพื่อตอบคำถามเจาะลึกจากข้อมูลชุดเดียวกัน

Find the high-CTR, still-small-reach ads worth scaling — then stay for follow-ups.

> ## 🔴 กฎเหล็ก 5 ข้อ (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error `The connector's server isn't
>    responding.` ที่**ดูเหมือน server พังทั้งที่ไม่ใช่** · เจอ error นี้ให้สงสัยวิธีเรียกของตัวเองก่อน
> 2. **เป็นงาน async** — ยิง tool ได้ `job_id` แล้วต้อง **poll `get_job` เองจนจบ** ตาม
>    `poll_hint.poll_after_seconds` · **ห้ามจบ turn คืนงานให้ user ระหว่างรอ** ·
>    **มี `job_id` มาให้แล้ว = ข้ามการยิง tool ไปเลย** (ดู § ทางลัดข้างล่าง)
> 3. **ห้ามเทข้อมูลดิบทั้งก้อนลงแชท** — คำนวณยอดรวมจากข้อมูลเต็ม แล้ว**พิมพ์ตารางแค่ 10 แถวต่อระดับ**
>    เสมอ (ดู § 5) · ข้อมูลเต็มยังอยู่กับเราไว้ตอบคำถามต่อ
> 4. **ตัวเลขทุกตัวต้องมาจาก `data` จริงเท่านั้น** — คีย์ไหนไม่มีก็ตัดคอลัมน์นั้นทิ้ง
>    **ห้ามเดา ห้ามเติมค่าที่ระบบไม่ได้ส่งมา ห้ามคำนวณเมตริกใหม่ที่ปลายทางไม่ได้ให้**
> 5. **ห้ามสร้าง widget / ฟอร์ม HTML / การ์ด UI เด็ดขาด** — ห้ามเรียก tool แสดงวิชวลทุกตัว
>    (`visualize` · `show_widget` · `render-ui` · Artifact) และ**ห้ามเขียน HTML/ฟอร์มเอง**
>    ถามด้วย **tool `AskUserQuestion` (ปุ่มตัวเลือก)** เท่านั้น · เรียกไม่ได้จริง ๆ =
>    **ถามเป็นข้อความแบบเลขข้อ (1 / 2 / 3) แล้วหยุดรอ user ตอบ** ห้ามเดาเองแล้วยิงต่อ

## Connector ที่ต้องมี · Required connector

| Connector | URL | ใช้ทำอะไร |
|---|---|---|
| **MaxxGPT** | `https://mcp.maxxgpt.ai/mcp` | `get_account_info` · `analysis_top_star` · `get_job` |

ไม่มี connector นี้ = แจ้ง user พร้อม URL แล้วหยุด อย่าเดินหน้าด้วยการเดา ·
**ชื่อ tool ของแต่ละ user อาจไม่ตรงเป๊ะ** (เปลี่ยนชื่อเองได้) → จับคู่จาก *ความสามารถ* ไม่ใช่ชื่อเป๊ะ ๆ

> **บัญชีโฆษณา · เพจ (MaxxGPT V4)** — ไม่ส่งอะไร = tool ใช้บัญชี/เพจที่ user เลือกไว้ในเว็บ MaxxGPT (กรณีปกติ) ·
> ทุก tool รับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ) ·
> id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
> user มีหลายบัญชีแล้วไม่ระบุ → ใช้ค่า default ไปก่อน แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (ทุกคำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง)
>
> **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
> `reason: OVER_QUOTA` = ผูกบัญชี/เพจเกินโควตาแพ็กเกจ (`ad_account_quota.linked > max_ad_accounts`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
> `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์นี้ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้

## ⚡ ทางลัด · มี `job_id` มาแล้ว = ข้ามไปวิเคราะห์เลย

**ถ้าข้อความของ user มี `job_id` ติดมา ให้ข้ามขั้น 1-2 ทั้งหมด** — ไม่ต้องถามอะไรเพิ่ม
**ไม่ต้องยิง `analysis_top_star` ใหม่** (ยิงใหม่ = เสียเวลา 1-5 นาที + เปลืองโควตา + อาจชน `JOB_ALREADY_RUNNING`)

**นับว่า "มี job_id" เมื่อ:** user พิมพ์/วางมาตรง ๆ (`job_id=…` · `[job_id=…]` · "ดูผลจากจ็อบ …" ·
วาง id ดิบ ๆ มาพร้อมบอกให้วิเคราะห์) · สกิลอื่นหรือเทิร์นก่อนหน้าส่งต่อมาให้ · งานตั้งเวลา/ระบบภายนอกแนบมา

```
job_id ที่ได้มา ──► get_job(job_id) ──► poll จน success ──► เช็คลายเซ็นข้อมูล ──► ตัด+แสดงผล
```

### ทำตามนี้

1. **`get_job(job_id)` ทันที** — ไม่ต้องยิง tool วิเคราะห์ · `processing` ก็ poll ต่อตามขั้น 3 ปกติ
2. **`get_account_info`** ยังต้องเรียก (1 ครั้งต่อ session) เพื่อเอา **สกุลเงิน + ชื่อบัญชี** ไปใส่หัวเรื่อง —
   แต่เรียก**ตอนไหนก็ได้** ไม่ต้องรอก่อน get_job
3. **เช็คว่าเป็นข้อมูลของหัวข้อนี้จริงไหม** — แถวต้องมี `Score` + `CPC` และ **ไม่มี** `CPM` และไม่มีคอลัมน์ผลลัพธ์ใด ๆ (ไม่มี `Inbox`/`Lead`/`Purchase`)
   → **ตรง** = วิเคราะห์ต่อตามขั้น 4-5 ปกติ
   → **ไม่ตรง** = ห้ามฝืนแปลง **บอก user ว่า job นี้เป็นผลของหัวข้ออื่น** แล้วชี้สกิลที่ตรงจากตารางข้างล่าง
     (ถ้า user ยืนยันให้ดูต่อ = แสดงเท่าที่คีย์จริงมี แล้วเขียนในหมายเหตุว่าไม่ใช่หัวข้อของสกิลนี้)
4. **ช่วงวันที่: `get_job` ไม่ได้คืนมาด้วย** — 🔴 **ห้ามเดา ห้ามใส่ช่วงมั่ว ๆ ในหัวเรื่อง**
   · user บอกช่วงมาด้วย = ใช้ตามนั้น · ไม่บอก = เว้นช่วงวันที่ในหัวเรื่องไว้ แล้วเขียนในหมายเหตุว่า
   "ผลชุดนี้มาจาก job ที่ส่งมา — ระบบไม่ได้แนบช่วงวันที่มาด้วย"
5. `code: JOB_NOT_FOUND` = **job_id ผิด หรือเป็นของ user คนอื่น** (job ผูกกับ login) →
   บอกตรง ๆ แล้วเสนอรันใหม่ตามขั้น 1-2 ปกติ · **ห้าม poll ซ้ำ** (`poll_hint.poll_after_seconds` = 0)
6. `job_status: failed` = งานเก่าตายไปแล้ว → เสนอรันใหม่ · `data` ว่าง `{}` = ช่วงนั้นไม่มีข้อมูล ไม่ใช่ error

### ตารางลายเซ็น — job_id นี้เป็นของหัวข้อไหน

| ลายเซ็นใน `data` | หัวข้อ | สกิลที่ควรใช้ |
|---|---|---|
| `Ad` เป็น **object** `{Close,Watch,Keep}` | Bottom Rank | `maxxgpt-rank-bottom-ads` |
| แถวมี `Score` + `CPC` · **ไม่มี `CPM`** และไม่มีคอลัมน์ผลลัพธ์ | Rising Stars | `maxxgpt-rank-rising-stars` |
| แถวมี `Score` + `Reach` + `Frequency` + `CPM` + `CPC` | Audience Growth | `maxxgpt-rank-audience-growth` |
| แถวมี `Score` + `CPM` + `Cost_per_*` (`per` ตัวเล็ก) · ไม่มี `Reach`/`CPC` | Top Rank | `maxxgpt-rank-top-ads` |
| แถวมี `Video_plays` + `Completion_Rate` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| แถวมี `Post_Engagement` + `post_engagement_rate` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| แถวมี `Inbox` + `MSS_VIEW` + `Cost_Per_Inbox` (`Per` ตัวใหญ่) | ทักแชท | `maxxgpt-analysis-message` |
| แถวมี `Lead` + `Cost_per_lead` | ลีด | `maxxgpt-analysis-leads` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **และ** มีคีย์ `Age`/`Gender` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **แต่ไม่มี** คีย์ `Age`/`Gender` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `data` มีคีย์ `OV` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |
| `data` มีบล็อก `CTR`/`CPM`/`FRQ` + `*_AD` | Ad Metric Benchmark (สเต็ป 2) | `maxxgpt-ad-metric-benchmark` |

⚠️ `purchase_meta` กับ `purchase_cpas` คอลัมน์เหมือนกันเป๊ะ แยกได้แค่จากคีย์ `Age`/`Gender` —
**ถ้าไม่มั่นใจให้บอก user ตรง ๆ ว่าเดาว่าเป็นหัวข้อไหน แล้วให้ยืนยัน** อย่าเงียบแล้วเดา

## ผังการทำงาน · Flow

```
ทางลัด · มี job_id ส่งมาให้แล้ว :  get_job(job_id) → poll จน success → ข้ามไปขั้น 4 เลย
ทางปกติ · ไม่มี job_id          :  0 → 1 → 2 → 3 → 4 → 5

0  get_account_info                      รู้ชื่อบัญชี + สกุลเงิน + โซนเวลา
1  ถามช่วงเวลา + spend ด้วย AskUserQuestion  ข้ามได้ถ้า user บอกมาแล้ว
2  ยิง tool ตาม § ขั้น 2                   ได้ { job_id, code }
3  วน get_job จน job_status = success     ตาม poll_hint · ห้ามจบ turn ระหว่างรอ
4  ตัดข้อมูล + คำนวณยอดรวม
5  พิมพ์สรุป + ตาราง markdown             อยู่ต่อเพื่อตอบคำถามจากข้อมูลชุดเดิม
```

### ขั้น 0 · รู้ก่อนว่าบัญชีไหน

เรียก `get_account_info` **หนึ่งครั้งต่อ session** เก็บ ชื่อบัญชี / `act_…` / สกุลเงิน / โซนเวลา ไว้ใช้ทุกขั้น

tool คืน `{ success, ad_account, page }` — ที่ต้องหยิบไปใช้:

| คีย์ใน `ad_account` | เอาไปใช้ตรงไหน | หมายเหตุ |
|---|---|---|
| `name` | ชื่อบัญชีในหัวเรื่อง | ชื่อบัญชีโฆษณา |
| `id` | วงเล็บต่อท้ายชื่อบัญชี | มี prefix `act_` มาแล้ว (`account_id` คือตัวไม่มี prefix) |
| `currency` | หน่วยเงินต่อท้ายตัวเลขเงินในตาราง | เช่น `THB` — `null` ได้ |
| `timezone_name` | ใช้คำนวณ "วันนี้" ตอนแปลงช่วงเวลา | เช่น `Asia/Bangkok` |
| `account_status` | เตือนไว้ในหมายเหตุถ้าบัญชีมีปัญหา | **เป็นตัวเลข ไม่ใช่ข้อความ** — `1` = ใช้งานได้ · ค่าอื่น (`2`,`3`,`101`,…) = บัญชีมีปัญหา |

- โซนเวลาใช้คำนวณ **"วันนี้"** ตอนแปลงคำพูดเป็นช่วงวันที่ — หาไม่เจอให้ใช้ `Asia/Bangkok`
- สกุลเงินใช้ต่อท้ายตัวเลขเงินทุกตัว — หาไม่เจอให้เว้นว่าง **ห้ามเดาว่าเป็น THB**
- บัญชีที่ `account_status` ไม่ใช่ `1` ยังดูผลย้อนหลังได้ ทำต่อได้ปกติ (เขียนเตือนไว้ในหมายเหตุ)

### ขั้น 1 · เลือกช่วงเวลา

**ถ้า user บอกมาครบแล้ว ไม่ต้องถามอะไรอีก** — บอกหนึ่งบรรทัดว่าใช้อะไร แล้วยิงต่อ

| user พูดมาแบบ | ทำอะไร |
|---|---|
| บอกครบ | ไม่ต้องถาม → ยิงเลย + บอกว่าใช้ช่วงไหน |
| **เคยรู้ช่วงเวลาแล้วใน session นี้** (รวมช่วงที่ได้จากสกิลวิเคราะห์ตัวอื่น) | ใช้ช่วงเดิมต่อ ยิงเลย + บอกว่าใช้ช่วงเดิม |
| ไม่บอกอะไรเลย | ถามด้วย `AskUserQuestion` |

**ห้ามถามช่วงเวลาซ้ำ** ถ้า session นี้เคยได้ช่วงเวลามาแล้ว — ใช้ค่าเดิมต่อ แล้วบอกว่ากำลังใช้ช่วงไหน ·
user เปลี่ยนทีหลังได้โดยบอกมาในแชท (ไม่ต้องถามใหม่ด้วยปุ่ม)

**`spend` (ยอดใช้จ่ายขั้นต่ำ)** = ตัดแถวเล็ก ๆ ที่เป็น noise ออกก่อนจัดอันดับ · เป็น**ตัวเลข** ไม่ใช่สตริง ·
user ไม่ได้ระบุ = ส่ง `0` (ไม่กรอง) ·
**ตั้ง `spend` แล้วต้องเขียนในหมายเหตุว่ากรองที่เท่าไร** ไม่งั้น user งงว่าทำไมแอดหาย

**ถามยังไง — ใช้ tool `AskUserQuestion` (ปุ่มตัวเลือก) เสมอ · ห้ามสร้าง widget/ฟอร์ม HTML · ห้ามพิมพ์คำถามเปล่า ๆ:**
สเปกคำถาม/ตัวเลือกอยู่ใน [references/output-format.md](references/output-format.md) § ถาม — **ถามทุกอย่างที่ยังไม่รู้ในการเรียกครั้งเดียว** ·
ที่รู้แล้วห้ามถามซ้ำ · user กด "Other" พิมพ์ช่วงเองได้ → แปลงเป็นวันที่ตามตารางในไฟล์นั้น

### ขั้น 2 · ยิง tool

```
analysis_top_star(date_start="YYYY-MM-DD", date_end="YYYY-MM-DD", spend=<number>)
```

หัวข้อนี้**ไม่มีเมตริกให้เลือก** — `spend` เป็นตัวกรองหลักตัวเดียว

- วันที่เป็น `YYYY-MM-DD` ตามโซนเวลาบัญชี · `date_start ≤ date_end`
- `spend` = ยอดใช้จ่ายขั้นต่ำที่จะเอามาจัดอันดับ · **เป็นตัวเลข ไม่ใช่สตริง** · `0` = เอาทุกแถว

ผลที่ได้คือ `{ job_id, code }` — **`code` มี 2 แบบที่ต้องแยก:**

| `code` | หมายถึง | ทำอะไรต่อ |
|---|---|---|
| `JOB_CREATED` | เริ่มงานใหม่แล้ว | poll ตามปกติ |
| `JOB_ALREADY_RUNNING` | **มีงานหัวข้อเดียวกันค้างอยู่ — `job_id` ที่ได้เป็นของงานเก่า** | poll ต่อได้ แต่ **ผลเป็นของช่วงวัน/ตัวเลือกที่สั่งไว้รอบก่อน ไม่ใช่ที่เพิ่งขอ** → บอก user ตรง ๆ + เขียนไว้ในหมายเหตุ แล้วเสนอรันใหม่หลังงานเก่าจบ |

> 1 user มีงานของ **tool เดียวกัน** ได้ทีละ 1 งาน (คนละ tool รันพร้อมกันได้ แต่เรายังยิงทีละตัวอยู่ดี)

### ขั้น 3 · รอผล (poll)

```
get_job(job_id)  →  { job_status, progression, data, poll_hint }
```

- `processing` → รอ `poll_hint.poll_after_seconds` วินาที **พิมพ์บรรทัดสั้น ๆ ให้ user เห็นว่ายังทำงานอยู่**
  (เช่น "ยังประมวลผลอยู่ ~40% — เช็คอีกครั้งใน 15 วิ") แล้ว poll ต่อ **ห้ามจบ turn**
- `success` → อ่าน `data` · **`data` อาจมาเป็นสตริง JSON → parse ก่อนใช้**
- `failed` + `data = {"error":"time_out"}` → เกินเพดานเวลา 5 นาที **ห้ามยิงซ้ำทันที**: บอก user ว่าช่วงที่ขอหนักไป
  เสนอย่นช่วงวัน (30 วัน → 7-14 วัน) หรือ poll ต่ออีกสักครู่ (งานเบื้องหลังอาจยังวิ่งและพลิกเป็น `success` เองได้)
- `poll_hint.poll_after_seconds = 0` = หยุด อย่า poll ต่อ
- error อื่น: `401` = token เว็บ MaxxGPT ใช้ไม่ได้/แพ็กเกจหมดอายุ → ให้ล็อกอินเว็บใหม่ ·
  `403` = แพ็กเกจไม่ครอบคลุมฟังก์ชันนี้ · `422` = ช่วงวันผิดรูป · `424` = ปลายทางมีปัญหา ลองใหม่ภายหลัง

## § 5 · กติกาตัดข้อมูล + วางตาราง (ห้ามข้าม)

| ส่วน | ใส่อะไร |
|---|---|
| สรุปรวม | **คำนวณจากข้อมูลเต็ม** ก่อนตัดแถว |
| ตาราง | 3 ตาราง: แคมเปญ / Ad set / โฆษณา (เรียงมาให้แล้วตาม `Score`) · **แต่ละระดับเอา 10 แถวแรก** ถ้าตัดออกให้เขียนใต้ตารางว่า "แสดง 10 จากทั้งหมด N" |
| คอลัมน์ | ชื่อ · `Spend` · `Impression` · `CTR` (หน่วย %) · `CPC` (จำนวนเงิน) · `Score` — 🔴 **ชุดนี้ไม่มี `CPM` และไม่มีคอลัมน์ผลลัพธ์ใด ๆ** อย่าไปหา |
| breakdown | **ไม่มี** — ชุดนี้ไม่มี breakdown อายุ/เพศ/อุปกรณ์ · user อยากได้ให้ชี้ไปสกิลตระกูล `maxxgpt-analysis-*` |
| ปิดท้าย | บรรทัดชวนถามต่อ (ดูด้านล่าง) |

- ระดับโฆษณา ให้ทำชื่อเป็นลิงก์ markdown ไปที่ `post_url` เสมอ (`[ชื่อ](post_url)`) · ไม่มี url = ชื่อเปล่า ๆ
- **ชื่อซ้ำกันได้จริง** (แคมเปญคนละ id ชื่อเดียวกัน · ad set ชื่อ `M-W` หลายตัว · โฆษณาชื่อ `-`) →
  ตารางระดับ ad set/โฆษณา **ต้องมีคอลัมน์แคมเปญกำกับ** และตอบคำถามรายตัวให้แนบ id
- **`Score` เรียงมาให้แล้ว — พิมพ์ตามลำดับเดิม อย่าเรียงใหม่** · `Score` ชุดนี้เป็น **0-100**
- 🔴 **`Score` คิดจาก CPM + CTR ไม่ได้คิดจากเมตริกที่ user เลือก** → อันดับ 1 อาจมีค่าเมตริกต่ำกว่าอันดับ 3 ได้
  (ของจริงเจอ ad set ROAS 5.62 ได้ Score 100 ส่วน ROAS 16.87 ได้ Score 0) · **ต้องเขียนไว้ในหัวเรื่อง
  ว่า "เรียงตามคุณภาพการส่ง (CPM+CTR) ไม่ใช่ตามค่าเมตริก"** ไม่งั้น user คิดว่าระบบคำนวณผิด ·
  user อยากได้อันดับตามเมตริกตรง ๆ = เรียงใหม่ให้ได้ แต่ต้องบอกว่าเปลี่ยนวิธีเรียงแล้ว
- ⚠️ **ชุดที่มี 2 แถวจะได้ `Score` = 100 กับ 0 เสมอ** (min/max normalize) — อย่าอ่านว่าตัวหนึ่งดีเลิศอีกตัวแย่สุดขีด

**ยอดรวมคำนวณยังไงถึงจะถูก:**

- รวมจากแถวระดับ **Campaign** (ไม่ใช่ Ad เพื่อไม่ให้นับซ้ำ) เว้นแต่ชุดนั้นมีแต่ระดับ Ad
- **ต้นทุนต่อผลรวม = `Spend รวม ÷ ผลรวม`** — **ห้ามเอาต้นทุนต่อผลรายแถวมาเฉลี่ย** (ได้เลขผิด)
- `CTR รวม` = `Clicks รวม × 100 ÷ Impression รวม` ไม่ใช่ค่าเฉลี่ยของ `CTR` รายแถว

**สรุปรวม 4 ช่อง (พิมพ์เป็นตารางเดียว):**

| ช่อง 1 | ช่อง 2 | ช่อง 3 | ช่อง 4 |
|---|---|---|---|
| จำนวนที่เจอ | ยอดใช้จ่ายรวม | CTR สูงสุดที่เจอ | ยอดแสดงผลรวม |

**บรรทัดชวนถามต่อ (พิมพ์ปิดท้ายเสมอ):**

```
ถามต่อได้: ขอตารางเต็ม (ทุกแถว) · เปลี่ยนช่วงเวลา · ดูหัวข้ออื่น
```

**หมายเหตุ (bullet `⚠️` ใต้ตาราง) ใส่เมื่อ:** ช่วงที่ขอรวมวันนี้ · ผลว่าง · ผลมาจาก job เก่า (`JOB_ALREADY_RUNNING`) ·
**ผลมาจาก `job_id` ที่ส่งมาโดยไม่รู้ช่วงวันที่** · บัญชีไม่ ACTIVE ·
**ใช้ `spend` กรอง (บอกว่ากรองที่เท่าไร ไม่งั้น user งงว่าทำไมแอดหาย)**

**ผลว่าง (`data` = `{}` หรือทุกชุดว่าง):** ยังพิมพ์หัวเรื่อง + สรุปตามปกติ แต่บอกเหตุผลแบบภาษาคน:
"ช่วงนี้ไม่เจอตัวที่เข้าข่ายดาวรุ่ง" → **ถ้าใส่ `spend` ไว้สูง ให้เสนอลดลงก่อนเป็นอย่างแรก**
แล้วค่อยเสนอขยายช่วงเวลา

## 📖 อ่านผลยังไง — สัญญาณของหัวข้อนี้

ส่วนนี้คือสิ่งที่ต้องใช้ตอนเขียนสรุป 2-4 บรรทัดหลังพิมพ์ตาราง · **อ่านก่อนพิมพ์สรุปทุกครั้ง**

> ### 🔴 กติกาของทั้งส่วนนี้ (ผิดข้อไหนคือให้คำแนะนำผิดกับเงินจริงของ user)
>
> 1. **ทุกข้อคือการเทียบ "ภายในชุดที่เพิ่งดึงมา" เท่านั้น** — ไม่ใช่ค่ามาตรฐานอุตสาหกรรม ·
>    **ห้ามพูดว่า "ต่ำกว่ามาตรฐาน" / "ค่าปกติควรอยู่ที่…"** เพราะสกิลนี้ไม่มีค่ามาตรฐานใด ๆ อยู่เลย ·
>    พูดว่า "ต่ำกว่าตัวอื่นในบัญชีช่วงนี้" แทน
> 2. 🔴 **ไม่มีเกณฑ์ตัวเลขตายตัว และจะไม่มี — นี่คือการตัดสินใจของเจ้าของระบบ ไม่ใช่ของที่ยังทำไม่เสร็จ**
>    ค่าที่ "ดี" ขึ้นกับแต่ละบัญชี/ธุรกิจ/สินค้า **ไม่มีสูตรกลาง** →
>    **ห้ามดึงตัวเลขเกณฑ์จากความรู้ทั่วไปหรือจากที่อื่นมาอ้าง** (เช่น "CTR ควรเกิน 1%",
>    "ROAS ต่ำกว่า 3 ถือว่าไม่ผ่าน") **แม้จะฟังดูสมเหตุสมผลก็ห้าม** ·
>    user ถามหา "เกณฑ์มาตรฐานเท่าไร" → **ตอบตรง ๆ ว่าไม่มีสูตรตายตัวเพราะขึ้นกับบัญชี**
>    แล้วเสนอทางที่ทำได้จริง: เทียบกับบัญชีตัวเองด้วย `maxxgpt-ad-metric-benchmark`
>    หรือเทียบกับช่วงเวลาก่อนหน้าของบัญชีเดียวกัน · **ห้ามขอโทษที่ไม่มีเกณฑ์** มันไม่ใช่ข้อบกพร่อง
> 3. **ห้ามสรุปจากแถวที่ `Impression` หรือ `Spend` น้อยมาก** — ตัวเลขยังไม่นิ่ง ·
>    เจอแถวแบบนี้ให้พูดว่า "ยังข้อมูลน้อยเกินจะสรุป" แทนที่จะชม/ตำหนิ
> 4. **พูดเป็น "สัญญาณ + สิ่งที่ควรไปดูต่อ" ไม่ใช่คำสั่ง** — สกิลนี้ไม่ได้เห็นครีเอทีฟ ไม่เห็นหน้าเว็บ
>    ไม่เห็นการตอบแชท จึงบอกได้แค่ว่า *ตัวเลขชี้ไปทางไหน* · **ห้ามฟันธงสาเหตุ**
> 5. **อัตราส่วนที่ปลายทางไม่ได้ให้มา คำนวณเองได้เฉพาะในคำอธิบาย** และต้องกำกับว่าเราคำนวณเอง ·
>    **ห้ามเพิ่มเป็นคอลัมน์ใหม่ในตาราง** (ขัดกฎเหล็กข้อ 4)
> 6. อยากได้ระดับ **High / Medium / Low เทียบค่ากลางของบัญชีจริง ๆ** → นั่นคือสกิล
>    `maxxgpt-ad-metric-benchmark` **ห้ามจัดระดับเองในสกิลนี้**

### สัญญาณที่อ่านได้จากคอลัมน์ของหัวข้อนี้

| เห็นแบบนี้ | อ่านว่า | ไปดูต่อที่ |
|---|---|---|
| `CTR` สูงกว่าตัวอื่นในชุด แต่ `Impression` ยังน้อย | **ของดีที่ยังไม่ถูกให้โอกาส** — นี่คือหัวใจของหัวข้อนี้ | เช็คผลลัพธ์จริงก่อนดันงบ (ดูข้อ 🔴 ล่าง) |
| `CPC` ถูก + `CTR` สูง | **ต้นทุนความสนใจถูก** — ซื้อคลิกได้ในราคาดีกว่าตัวอื่นในบัญชี | ตัวที่ควรพิจารณาเพิ่มงบก่อนเพื่อน |
| `CTR` สูงแต่ `CPC` ก็แพง | คนคลิกเยอะแต่การประมูลแพง — **แข่งในกลุ่มที่ราคาสูง** | ลองกลุ่มเป้าหมายอื่น |
| `Impression` น้อยมาก (หลักร้อย) | 🔴 **ตัวเลขยังไม่นิ่ง** — CTR สวยเพราะฐานน้อย **ห้ามเชียร์ให้ดันงบหนัก** | ค่อย ๆ เพิ่มงบแล้วดูซ้ำ |
| แถวท้าย ๆ ตาราง `Score` = 0 | **ไม่ใช่ดาวรุ่ง** — ชุดนี้คืนทุกแถวที่ผ่าน `spend` มา ไม่ได้คัดมาแต่ตัวเด่น | พูดถึงเฉพาะแถวบน ๆ |

- 🔴 **หัวข้อนี้ไม่มีคอลัมน์ผลลัพธ์เลย** (ไม่มี `Inbox`/`Lead`/`Purchase`) →
  **บอกได้แค่ "มีแวว" ห้ามบอกว่า "ทำเงินได้"** · ก่อนแนะนำให้เพิ่มงบจริง **ต้องบอก user ให้ไปเช็คผลลัพธ์
  ของตัวนั้นที่สกิล `maxxgpt-analysis-*` ที่ตรงกับ objective ก่อน** — CTR สูงแต่ไม่มีใครซื้อก็มีจริง
- 🔴 **ห้ามเรียกทั้งชุดว่า "ดาวรุ่ง"** — พูดว่า "เรียงจากมีแววมากสุดลงมา"
- **`Score` = CPM 40% + CTR 60% normalize ในชุด** — ชุด 2 แถวได้ 100 กับ 0 เสมอ
- **การเพิ่มงบเร็วเกินไปทำให้ตัวที่กำลังดีเสียได้** — ถ้าจะแนะนำ ให้แนะนำแบบค่อยเป็นค่อยไป
  และย้ำว่าสกิลนี้ **แก้งบให้ไม่ได้**

**เขียนสรุปยังไงให้ใช้ได้จริง:** หยิบมา **2-3 สัญญาณที่เด่นที่สุด** พอ (ไม่ใช่ไล่ทุกข้อ) ·
อ้างชื่อ + ตัวเลขของแถวจริงเสมอ · ปิดท้ายด้วย **คำถามชวนเจาะต่อ 1 ข้อ** ที่ตอบได้จากข้อมูลชุดเดิม

## หลังแสดงผล — อยู่ต่อเพื่อตอบคำถาม

หลังพิมพ์ตารางแล้ว **เขียนสรุปสั้น ๆ 2-4 บรรทัด** โดยใช้สัญญาณจาก
[§ อ่านผลยังไง](#-อ่านผลยังไง--สัญญาณของหัวข้อนี้) ข้างบน แล้วบอกว่าถามต่อได้
— **อย่าเทข้อมูลดิบซ้ำลงในแชท** · **ห้ามพิมพ์สรุปโดยไม่ได้อ่าน § อ่านผลยังไง ก่อน**

ตอบคำถามต่อจาก **ข้อมูลชุดเดิมที่ดึงมาแล้ว** ห้ามยิง tool ซ้ำ เว้นแต่:

| user ขอ | ทำอะไร |
|---|---|
| ตัวเลข/อันดับ/เจาะแถว/ตารางเต็ม/ระดับอื่น | ตอบจากข้อมูลเดิม **ไม่ต้องยิงใหม่** |
| เปลี่ยนช่วงเวลา / เปลี่ยน `spend` | ยิงใหม่ (จำช่วงเวลาเดิมไว้ ไม่ต้องถามซ้ำ) |
| เปลี่ยนไปหัวข้ออื่น | **สกิลนี้ทำหัวข้อเดียว** → ชี้ไปสกิลที่ตรง (ดูตารางสกิลพี่น้อง) แล้วส่งช่วงเวลาเดิมต่อไปให้ |
| "ปิดตัวนี้ให้หน่อย" / "เพิ่มงบตัวนี้" | **สกิลนี้ทำไม่ได้** — บอกตรง ๆ ว่าดูได้อย่างเดียว แล้วชี้ไป Ads Manager หรือสกิลจัดการงบ |
| อยากดู breakdown อายุ/เพศ/อุปกรณ์ | **ไม่มีในชุดนี้** — ชี้ไปสกิลตระกูล `maxxgpt-analysis-*` |

ขอตารางเต็ม = พิมพ์ทุกแถวเป็น markdown ในแชท · ถ้ายาวมากให้แบ่งตามระดับ
แล้วถามว่าจะดูระดับไหนก่อน

## ข้อควรระวังเรื่องตัวเลข

- **สตางค์/หน่วยเงิน**: ค่าที่ปลายทางส่งมาเป็นหน่วยเงินปกติแล้ว — ใช้ตามที่ได้มา ห้ามคูณ/หาร 100
- **`CTR` เป็นเปอร์เซ็นต์อยู่แล้ว** (เช่น `1.84` = 1.84%) → พิมพ์ต่อท้ายด้วย `%` **ห้ามคูณ 100 ซ้ำ**
- 🔴 **ต้นทุนต่อผล = `0` แปลว่า "ไม่มีผลลัพธ์" ไม่ใช่ "ถูก"** — แถวที่เมตริกหลัก = 0 ได้คอลัมน์ต้นทุนเป็น `0`
  → **ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่าตัวไหนถูกสุดเสมอ**
- **`ROAS` เป็นเท่า ไม่ใช่ %** → หัวคอลัมน์เขียนว่า "ROAS (เท่า)"
- `Impression` **ไม่มี s** · **ชื่อคอลัมน์อ่านจากแถวจริงเสมอ** (`Object.keys(rows[0])`) คีย์ไหนไม่มี = ตัดคอลัมน์ทิ้ง
- 🔴 **ชุดนี้คืน *ทุกแถวที่ผ่าน `spend`* เรียงตาม `Score` — รวมแถวที่ `Score` = 0 ด้วย**
  → **ห้ามเรียกทั้งชุดว่า "ดาวรุ่ง"** แถวท้าย ๆ ไม่ใช่ · พูดให้ตรงว่า "เรียงจากมีแววมากสุดลงมา"
- **ไม่มีคอลัมน์ผลลัพธ์ (`Inbox`/`Lead`/`Purchase`) ในชุดนี้เลย** — user ถามถึงยอดผลลัพธ์ของตัวที่เจอ
  ให้ชี้ไปสกิล `maxxgpt-analysis-*` ที่ตรงกับ objective **ห้ามเดาตัวเลข**
- `CPC` เป็นจำนวนเงินต่อคลิก → พิมพ์เป็นจำนวนเงิน 2 ตำแหน่ง + สกุลเงิน
