# หน้าตาข้อมูลที่ได้จาก `get_job` — ต่อหัวข้อ

อ่านไฟล์นี้ตอนจะแปลงผลเป็นตาราง เพื่อรู้ว่าจะหยิบคีย์ไหน

> ## 🔑 กฎเดียวที่ห้ามข้าม
> **อ่านชื่อคีย์จากแถวจริงเสมอ** (`Object.keys(rows[0])`) แล้วค่อยเลือกคอลัมน์ตามตารางข้างล่าง ·
> ตารางนี้คือ *สิ่งที่คาดว่าจะเจอ* ไม่ใช่สัญญาตายตัว — ปลายทางเป็น flow ของเว็บ MaxxGPT
> ที่แก้ไขได้โดยไม่ผ่านสกิลนี้ · **คีย์ไหนไม่มี = ข้ามคอลัมน์นั้นไป ห้ามเดาค่า ห้ามคำนวณแทน**

## รูปแบบตาม 2 กลุ่ม

`data` จาก `get_job` อาจมาเป็น **สตริง JSON → ต้อง parse ก่อน** · `{}` ว่าง = ไม่มีแถวเข้าเกณฑ์ (ไม่ใช่ error)

**กลุ่ม A — `top_rank` · `rising_stars` · `audience_growth`** (รายการเรียงอันดับตรง ๆ)

```
{ "Ad":[…], "Adset":[…], "Campaign":[…] }
```

**กลุ่ม B — `bottom_rank`** (แยกเป็น 3 ถังตามสิ่งที่ควรทำ)

```
{ "Ad":      {"Close":[…], "Watch":[…], "Keep":[…]},
  "Adset":   {"Close":[…], "Watch":[…], "Keep":[…]},
  "Campaign":{"Close":[…], "Watch":[…], "Keep":[…]} }
```

> ## 🔴 `bottom_rank` ไม่ได้คืนแค่ "ตัวที่แย่" — มันคือ **การคัดแยกทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก**
> โฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดนั้นและมี `Spend` > 0 (และถึง `spend` ที่กรอง) จะถูกจัดลงถังใดถังหนึ่ง **รวมตัวที่ทำได้ดีที่สุดด้วย** ·
> โฆษณาที่ตั้งเป้าเป็นผลลัพธ์อื่นไม่อยู่ในถังใดเลย · มีแถวที่ได้ผลลัพธ์ไม่ถึง 4 แถว = ไม่มีถัง `Keep` (ผล 0 = `Close` · ที่เหลือ = `Watch`)

| ถัง | ความหมายที่ต้องสื่อให้ user | หัวข้อแท็บที่ใช้ |
|---|---|---|
| `Keep` | **ทำได้ดี ปล่อยวิ่งต่อ** — ถังนี้คือตัวที่ควรเก็บไว้ (ของจริงเจอตัวที่ต้นทุน/แชทถูกที่สุดของบัญชีอยู่ในนี้) | 🟢 ทำได้ดี ปล่อยวิ่งต่อ (Keep) |
| `Watch` | ก้ำกึ่ง — **เฝ้าดูต่อ** ยังไม่ต้องรีบปิด | 🟡 เฝ้าดูต่อ (Watch) |
| `Close` | แย่ชัดเจน — **ควรปิด** | 🔴 ควรปิด (Close) |

⚠️ **ห้ามเรียกทั้งชุดนี้ว่า "โฆษณาที่ทำได้แย่"** และ **ห้ามบอกว่าของในถัง `Keep` เป็นตัวไม่ดี** —
พูดให้ตรงว่า "คัดแยกโฆษณาที่ตั้งเป้าผลลัพธ์นี้เป็น 3 กลุ่ม: เก็บไว้ / เฝ้าดู / ควรปิด"

⚠️ **ห้ามสรุปเองว่าให้ปิดตัวไหน** — ถังที่ปลายทางจัดมาให้แล้วคือคำตอบ หน้าที่เราคือแสดงและอธิบาย

## คอลัมน์ของแถว

**ปลายทางตัดคอลัมน์มาให้แล้ว — ได้มาน้อยกว่าที่คิด** คอลัมน์ฐานที่มีทุกหัวข้อ:
`<level>_id` · `<level>_name` · `Spend` · `Impression` · `Clicks` · `CTR` · ระดับ Ad มี `post_url` (ว่างได้)

| หัวข้อ | tool | คอลัมน์ที่เพิ่มมา | เรียงมาให้แล้วตาม |
|---|---|---|---|
| `top_rank` | `analysis_good_inbox` / `_lead` / `_purchase` / `_roas` | `CPM` · `Purchase` · **คอลัมน์ผลของ metric** · **คอลัมน์ต้นทุนของ metric** (มีเฉพาะ inbox / lead) · **`Score`** | `Score` มาก→น้อย |
| `bottom_rank` | `analysis_bad_inbox` / `_lead` / `_purchase` | `CPM` · `Purchase` · คอลัมน์ผล + ต้นทุนของ metric · **ไม่มี `Score`** | ภายในถัง ไม่ได้เรียงเป็นพิเศษ |
| `rising_stars` | `analysis_top_star` | **`CPC`** · **`Score`** · **ไม่มี `CPM` และไม่มีคอลัมน์ผลลัพธ์ใด ๆ** | `Score` มาก→น้อย |
| `audience_growth` | `analysis_top_aware` | `Reach` · `Frequency` · `CPM` · `CPC` · `Score` | `Score` มาก→น้อย |

⚠️ **`Objective` / `Result` / `Result_indicator` / `MSS_VIEW` / `Purchase_meta` / `Purchase_CPAS` ไม่ได้ติดมา**
ในผลลัพธ์ของชุดนี้ (มีอยู่แค่ภายใน flow) — อยากได้ต้องไปดูที่สกิล export report

### 🔴 `Score` — สูตรต่างกันตามหัวข้อ และ **ไม่ได้คิดจากเมตริกที่ user เลือก**

`good_*` · `top_star` · `top_aware` มีคอลัมน์ **`Score` แบบ 0-100** · แถวเรียงตาม `Score` มาก→น้อย
มาให้แล้ว → **ส่งเข้าตารางตามลำดับเดิม อย่าเรียงใหม่**

**สูตร (ปรับสเกล 0-100):**

- `good_*` = `0.4 × (CPM ยิ่งต่ำยิ่งดี) + 0.6 × (CTR ยิ่งสูงยิ่งดี)`
- `top_star` = `0.4 × (CTR ยิ่งสูงยิ่งดี) + 0.6 × (Impression ยิ่งน้อยยิ่งดี)`
- `top_aware` = `0.4 × (CPM ยิ่งต่ำยิ่งดี) + 0.6 × (Frequency ยิ่งต่ำยิ่งดี)`

**เทียบกันเฉพาะภายในชุดที่คืนมา** (ดีสุดทั้งสองคอลัมน์ = 100 · แย่สุดทั้งสองคอลัมน์ = 0)

⚠️ **แปลว่าอันดับ 1 ไม่ใช่ "ตัวที่เมตริกดีที่สุด"** — ของจริงเจอใน `top_rank` + `metric=roas`:

| แถว | ROAS | Score |
|---|---|---|
| ad set A | **5.62** | **100** |
| ad set B | **16.87** | **0** |

B มี ROAS สูงกว่า 3 เท่า แต่ Score 0 เพราะ CPM แพงกว่า/CTR ต่ำกว่า (และ B ใช้เงินแค่ 543 บาท
ขณะที่ A ใช้ 11,841 บาท) · **เวลาอธิบายให้ user ต้องบอกว่า "เรียงตามคุณภาพการส่ง (CPM+CTR)
ไม่ใช่ตามค่าเมตริก"** ไม่งั้น user จะคิดว่าระบบคำนวณผิด · ถ้า user อยากได้อันดับตามเมตริกตรง ๆ
ให้เรียงใหม่ตามคอลัมน์นั้นเอง **แล้วบอกว่าเปลี่ยนวิธีเรียงให้แล้ว**

⚠️ **ชุดที่คืนมา 2 แถวจะได้ `Score` แค่ 100 กับ 0 หรือ 60 กับ 40** (min/max normalize ทีละคอลัมน์) — อย่าอ่านว่า "ตัวหนึ่งดีเลิศ
อีกตัวแย่สุดขีด" · ชุดที่มีแถวเดียวก็อ่านค่าไม่ได้เหมือนกัน

⚠️ **ต่างจาก `Score` ในหัวข้อ `Recomment` ของสกิล performance-analysis ที่เป็น 0-1** — อย่าจำสลับกัน

### สิ่งที่ tool คืนมา ≠ "เฉพาะตัวที่เข้าเกณฑ์"

| tool | คืนมาเท่าไร (ของจริง บัญชี 41 ads) |
|---|---|
| `good_*` | **คัดมาแล้วจริง ๆ ไม่เกิน 5 แถวต่อระดับ** (ว่างทั้งระดับเมื่อตัวที่ได้ผลลัพธ์มีไม่ถึง 5 ตัว) — 5 ads / 2 ad sets / 1 campaign |
| `bad_*` | **ทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก** แยก 3 ถัง (42 ads รวมทุกถัง) |
| `top_star` / `top_aware` | **ทุกแถวที่ผ่าน `spend`** เรียงตาม `Score` — **รวมแถวที่ `Score` = 0 ด้วย** → แถวท้าย ๆ ไม่ใช่ "ดาวรุ่ง" อย่าเรียกรวมทั้งชุดว่าดาวรุ่ง |

### ⚠️ ชื่อซ้ำกันได้ ต้องมี id กำกับ

ของจริงเจอ **แคมเปญ 2 ตัวชื่อเดียวกันเป๊ะ** (`[FB X AI สด] INBOX *Post หน้าเพจ` — คนละ `campaign_id`)
และชื่อ ad set ซ้ำข้ามแคมเปญ (`M-W`, `New Engagement Ad Set`) · ชื่อโฆษณาก็ซ้ำ (`-`, `รูป`, `video`) →
**ตารางระดับ ad set / โฆษณา ให้กำกับด้วย id ของแถวนั้น** (แถวไม่มีชื่อ/ID แคมเปญติดมา) และถ้า user ถามถึงตัวใดตัวหนึ่งให้ตอบพร้อม id

**คอลัมน์ต้นทุนต่อผลที่คู่กับ metric แต่ละตัว:**

| `metric` | คอลัมน์ผล | คอลัมน์ต้นทุน |
|---|---|---|
| `inbox` | `Inbox` | `Cost_per_Inbox` |
| `lead` | `Lead` | `Cost_per_Lead` |
| `purchase` | `Purchase` | `Cost_per_Purchase` (เฉพาะ `bottom_rank` · `top_rank` ไม่มี ให้ใช้ `ROAS`) |
| `roas` | `Purchase_Value` | `ROAS` (ไม่มีต้นทุนต่อผล) |

⚠️ ชื่อคอลัมน์สะกดตามของจริง — ชุดนี้ใช้ `Cost_per_Inbox` / `Cost_per_Lead` / `Cost_per_Purchase`
(**`per` ตัวเล็กทั้งหมด**) ซึ่ง **ต่างจากสกิล performance-analysis ที่ใช้ `Cost_Per_Inbox`** ·
`Impression` ไม่มี s

### 🔴 กับดักที่ทำให้อันดับผิด: ต้นทุนต่อผล = `0` เมื่อไม่มีผลลัพธ์

แถวที่เมตริกหลัก = 0 จะได้ **คอลัมน์ต้นทุนเป็น `0` ไม่ใช่ `null`** → เรียง "ถูกสุด" จากน้อยไปมากตรง ๆ
แล้ว **แถวที่ไม่ได้ผลอะไรเลยจะขึ้นอันดับ 1**

**กติกา:** ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่า "ตัวไหนถูกสุด" เสมอ ·
เรื่องนี้สำคัญกับ `bottom_rank` เป็นพิเศษ เพราะถังนั้นเต็มไปด้วยแถวที่ผลเป็น 0
