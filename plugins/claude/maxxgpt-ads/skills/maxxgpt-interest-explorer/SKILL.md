# MaxxGPT — Interest Explorer (หน้าค้น interest)

ส่งมอบ **หน้าเว็บส่วนตัวของ user** (Artifact) ที่ค้น interest ของ Meta ได้เอง แทนที่จะตอบเป็นข้อความในแชท
รอบเดียวจบ — user เก็บลิงก์ไว้เปิดใช้ได้เรื่อย ๆ ชุดที่บันทึกไว้ก็ยังอยู่.

> ## 🔴 กฎเหล็ก (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error
>    `The connector's server isn't responding.` ที่ดูเหมือน server พังทั้งที่ไม่ใช่
> 2. **ห้าม publish โดยไม่ส่ง `capabilities`** — manifest ไม่ได้อยู่ในไฟล์ HTML แต่เป็น
>    argument ของตอน publish · ลืมส่ง = `claude.use()` คืน `null` ทุกตัว หน้าจะเปิดได้แต่
>    ค้นไม่ได้ เซฟไม่ได้ โหลด CSV ไม่ได้ **โดยไม่มี error ให้เห็น** (เคยเกิดจริงมาแล้ว)
> 3. **ห้ามฮาร์ดโค้ดชื่อ connector และห้ามใส่ชื่อสำรอง** — ชื่อเป็นของ user แต่ละคน
>    ต้อง**ค้นหาจาก tool ที่ connector นั้นมี** ตามขั้น 1 แล้วประกาศ **ชื่อเดียวที่หาเจอ** ·
>    ใส่ชื่อเผื่อไว้ = กล่องขออนุญาตเด้งถามซ้ำทุกครั้งที่เปิดหน้า (ดูขั้น 4)
> 4. **ต้องยิง `search_interest` จริงอย่างน้อยหนึ่งครั้งก่อน publish** — กฎของ artifact คือ
>    ห้าม publish หน้าที่เรียก connector tool โดยไม่เคยเห็น request/response จริงในเซสชันนั้น
> 5. **หน้านี้แชร์ต่อให้คนอื่นไม่ได้** — capability `mcp` ปิดการแชร์สาธารณะไว้ และ tool ทุกตัว
>    ถูกเรียกด้วยเครดิตของ *คนเปิดหน้า* → ใครอยากใช้ ต้อง publish หน้าของตัวเอง **ห้ามบอก user
>    ว่าส่งลิงก์นี้ให้ลูกค้าหรือทีมได้**
> 6. **บัญชีโฆษณา · เพจ (MaxxGPT V4)** — ไม่ส่งอะไร = tool ใช้บัญชี/เพจที่ user เลือกไว้ในเว็บ MaxxGPT (กรณีปกติ) ·
>    ทุก tool รับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ) ·
>    id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
>    user มีหลายบัญชีแล้วไม่ระบุ → ใช้ค่า default ไปก่อน แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (ทุกคำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง)
>
>    **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
>    `reason: OVER_QUOTA` = ผูกบัญชี/เพจเกินโควตาแพ็กเกจ (`ad_account_quota.linked > max_ad_accounts`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
>    `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์นี้ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้
> 7. **เจอหน้าเดิมที่ทำงานแทบเหมือนกัน = ต้องถามก่อนเสมอ** (ขั้น 3) ว่าจะอัปเดตตัวเดิม
>    หรือสร้างใหม่ · **ห้ามตัดสินใจแทน** — สร้างใหม่ทับความคาดหวังของเขา = ชุดที่บันทึกไว้
>    ไม่ตามมา และลิงก์ที่เขาแปะไว้ที่อื่นชี้ไปหน้าเก่า

## ผังการทำงาน · Flow

```
1  หา connector ตัวจริง ──► ชื่อที่ user ตั้งไว้ (ห้ามเดา)
2  ยิง search_interest จริง 1 ครั้ง ──► ยืนยันว่าเรียกได้ + ได้เห็น response จริง
3  เคยมีหน้าแบบนี้อยู่แล้วไหม ──► มี = 🔴 ถามก่อน (อัปเดตตัวเดิม / สร้างใหม่)
                                └─ ไม่มี = publish ใหม่ได้เลย
4  publish พร้อม capabilities manifest ──► ส่งลิงก์ + อธิบายวิธีใช้สั้น ๆ
```

### ขั้น 1 · หา connector ตัวจริง (ห้ามข้าม)

**ชื่อ connector เป็นของ user แต่ละคน** — บางคนตั้งว่า `MaxxGPT MCP` บางคน `MaxxGPT`
บางคนตั้งเป็นชื่อบริษัทตัวเอง และ artifact รับได้เฉพาะ **ชื่อที่แสดง** เท่านั้น
(ไม่รับ id ไม่รับ URL — ในหน้าเว็บก็มองไม่เห็น URL เช่นกัน เป็นข้อกำหนดถาวรของ runtime)

> ### 🔴 ต้องเป็น **claude.ai connector** เท่านั้น — ของที่ปลั๊กอินประกาศใช้ไม่ได้
> ปลั๊กอิน `maxxgpt-ads` ประกาศ MCP server ชื่อ **`maxxgpt`** ไว้ใน `.mcp.json` ·
> อันนั้นเป็น **local MCP server ของ Claude Code** — ใช้ยิง tool ในแชทได้ แต่
> **หน้า artifact เรียกไม่ได้** (สเปกระบุว่า `server` รับเฉพาะ claude.ai connector ·
> local MCP server ไม่นับ) · **ชื่อสองอันนี้ไม่ต้องตรงกันและมักไม่ตรง**
>
> ⚠️ **ยิง `search_interest` ในแชทได้ ไม่ได้แปลว่าจะ publish ได้** — ถ้าเขามีแต่ server
> จากปลั๊กอิน สกิลจะทำงานในแชทได้ปกติแต่หน้าที่ publish ออกไปจะขึ้น "ยังเรียกข้อมูลไม่ได้"
> → เจอแบบนี้ **ห้าม publish** ให้บอกเขาไปเพิ่ม connector ที่ claude.ai → Settings →
> Connectors ด้วย URL `https://mcp.maxxgpt.ai/mcp` ก่อน แล้วค่อยกลับมาเรียกสกิลใหม่

**เบาะแสไว้ใช้หา (ไม่ใช่ค่าที่เอาไปประกาศ)** — ชื่อมักมีคำว่า `MaxxGPT` อยู่ ·
URL ของ server คือ `https://mcp.maxxgpt.ai/mcp` (ของเดิม `https://mcp-beta.maxxgpt.ai/mcp`)
ใช้เบาะแสนี้ตอนต้องถาม user ให้เขาไปดูที่ Settings → Connectors เท่านั้น

1. เรียกสกิล **`artifact-capabilities`** — มันจะพิมพ์รายชื่อ **claude.ai connector** ของ
   เซสชันนี้พร้อมชื่อที่แสดงจริง คู่กับ id ที่ใช้ใน tool name (`mcp__<id>__<tool>`) ·
   **connector ที่ใช้ได้มีแค่ที่อยู่ในรายการนี้** — ตัวที่มาจาก `.mcp.json` ของปลั๊กอินจะไม่อยู่
2. **จับคู่จากความสามารถ ไม่ใช่จากชื่อ** — หา connector ที่มีทั้ง `search_interest`
   และ `suggest_interest` · ตัวที่มีสองตัวนี้คือตัวที่ใช่ ไม่ว่าจะชื่ออะไร
   (ชื่อที่มีคำว่า MaxxGPT แต่ไม่มีสอง tool นี้ = ไม่ใช่ อย่าหยิบมาใช้)
3. เจอหลายตัวที่เข้าเกณฑ์ → ถามผู้ใช้ว่าจะใช้ตัวไหน บอกชื่อที่เจอทั้งหมด
   และบอก URL ข้างบนให้เขาไปเทียบเอง **ห้ามเดา ห้ามประกาศทั้งหมด**
4. ไม่เจอเลย → แจ้ง user ให้ไปต่อ connector ที่ URL ข้างบน แล้วหยุด **ห้าม publish ทิ้งไว้**

ผลของขั้นนี้ = **ชื่อเดียว** ที่จะเป็น `server` ตัวเดียวใน manifest ตอน publish
(ดูกล่องแดงในขั้น 4 ว่าทำไมห้ามใส่มากกว่าหนึ่งชื่อ)

### ขั้น 2 · ยิงของจริงหนึ่งครั้ง

เรียก `search_interest` ด้วยคำค้นสั้น ๆ (`limit: 3` พอ) เพื่อสองอย่าง:
- ยืนยันว่า connector ตอบจริง ไม่ใช่แค่ปรากฏในรายการ
- ทำให้เข้าเงื่อนไข "เคยเห็น response จริง" ก่อน publish

ได้ `{status:200, success:true, interests:[…]}` = ผ่าน · ได้ error = แจ้ง user แล้วหยุด.

### ขั้น 3 · เคย publish ให้เขาแล้วหรือยัง — 🔴 **เจอของเดิมต้องถามก่อน**

ใช้ `Artifact action:"list"` แล้วมองหา **หน้าที่ทำงานแทบเหมือนกัน** — ไม่ใช่แค่ชื่อตรงเป๊ะ
นับว่า "แทบเหมือนกัน" เมื่อชื่อหรือคำอธิบายสื่อถึงการค้น interest ของ Meta เช่น
`ค้น Interest Meta` · `Interest Explorer` · `หา interest` · `interest Meta` · `ค้นความสนใจ`
ชื่ออื่นที่ user ตั้งเองแต่เนื้อหาเป็นเรื่องเดียวกัน ก็ให้นับด้วย.

**ไม่เจอ** → publish ใหม่ได้เลย พร้อม `favicon: "🎯"` ไม่ต้องถาม

**เจอ (ตัวเดียวหรือหลายตัว)** → **หยุดแล้วถาม user ก่อน ห้ามเลือกเอง**
ใช้ `AskUserQuestion` บอกไปว่าเจอหน้าอะไรบ้าง (ชื่อ + วันที่แก้ล่าสุด) แล้วให้เลือก:

| ตัวเลือก | ผลที่ตามมา — **ต้องบอก user ให้ครบ** |
|---|---|
| **อัปเดตตัวเดิม** (ค่าที่ควรแนะนำ) | ลิงก์เดิมไม่เปลี่ยน · **ชุดที่บันทึกไว้ยังอยู่ครบ** · คนที่เปิดหน้านี้ค้างอยู่จะเห็นเวอร์ชันใหม่ทันที |
| **สร้างใหม่แยกอีกหน้า** | ได้ลิงก์ใหม่ · **เริ่มจากศูนย์ ชุดที่บันทึกไว้เดิมไม่ตามมา** (`db` ผูกกับ artifact ไม่ใช่ไฟล์) · ของเดิมยังอยู่ที่ลิงก์เก่า ไม่ได้ถูกลบ |

เจอหลายตัวแล้วเขาเลือก "อัปเดตตัวเดิม" → ถามต่อว่าอันไหน (อย่าเดา)

**ลงมือตามที่เขาเลือก**

| เลือก | ทำอะไร |
|---|---|
| อัปเดตตัวเดิม | `action:"read"` ที่ URL นั้น**ก่อนเสมอ** (บังคับ ไม่งั้น publish จะถูกปฏิเสธ) แล้ว publish ด้วย `url` เดิม · **ห้ามใส่ `favicon`** · ห้ามใส่ `contract` |
| สร้างใหม่ | publish โดย**ไม่ใส่** `url` · ใส่ `favicon: "🎯"` · ตอนส่งลิงก์ให้ย้ำอีกครั้งว่าอันเก่ายังอยู่ที่ลิงก์เดิม |

### ขั้น 4 · publish

ไฟล์: `assets/interest-explorer.html` — **publish ทั้งไฟล์ตามที่เป็น ห้ามแก้เนื้อไฟล์**
manifest ฉบับเต็มอยู่ที่หัวไฟล์และใน `references/publish-manifest.md`

```
capabilities:
{
  "mcp": { "servers": [
    { "server": "<ชื่อที่เจอในขั้น 1 — ตัวเดียว>", "tools": ["search_interest", "suggest_interest"] }
  ] },
  "db": {},
  "downloads": true,
  "sample": {}
}
```

> ### 🔴 ประกาศ connector **ชื่อเดียว** เท่านั้น
> ห้ามใส่ชื่อสำรองเผื่อไว้เด็ดขาด — **เคยลองแล้วและต้องถอยกลับ**
> หน้าขออนุญาตของ Claude พิมพ์**หนึ่งแถวต่อหนึ่งชื่อที่ประกาศ** ชื่อที่ user ไม่มีจะขึ้นว่า
> *"No matching connector found"* พร้อมปุ่ม *Add custom* และทำให้กล่องขออนุญาต
> **เด้งถามซ้ำทุกครั้งที่เปิดหน้า** แทนที่จะจำว่าอนุญาตแล้ว · ชื่อเดียวที่ตรง = ถามครั้งเดียวจบ

- `contract` **ห้ามส่ง** ตอน update (ปล่อยให้ carry forward) · publish ใหม่ก็ไม่ต้องส่ง
- `description` สั้น ๆ: "ค้น interest ของ Meta ผ่าน MaxxGPT ไล่ดูตัวที่เกี่ยวข้อง แล้วเก็บเป็นชุดไว้ใช้ต่อ"

## หน้าที่ได้ ทำอะไรได้บ้าง (ใช้เขียนสรุปให้ user)

| ส่วน | ทำอะไร |
|---|---|
| **ให้ Claude หา interest ให้** | พิมพ์ว่าขายอะไร ขายให้ใคร → Claude เลือกคำค้น 6 คำ (ไทย+อังกฤษ) → หน้าเว็บค้นทีละคำแล้วรวมผล ตัดตัวซ้ำ เรียงจากตรงที่สุด |
| **ช่องค้นหา** | พิมพ์คำค้นเอง กดปุ่มถึงจะค้น (ไม่ค้นอัตโนมัติ) |
| **ไล่ดูตัวที่เกี่ยวข้อง** | คลิกชื่อ interest → `suggest_interest` → ไล่ต่อเป็นสายได้ 8 ชั้น กดย้อนได้ |
| **ตะกร้า** | ติ๊กเลือก แล้วก๊อปชื่อ / ก๊อป id / ชื่อ+id / ดาวน์โหลด CSV |
| **ชุดที่บันทึกไว้** | ตั้งชื่อชุดแล้วบันทึก อยู่กับหน้านี้ เปิดครั้งหน้ายังอยู่ |
| **ตัวกรอง** | เรียง 4 แบบ · กรองทีละคำค้น · ซ่อน "ตัวกว้างทั่วไป" |

1. **ตัวเลข audience เป็นค่าประมาณของ Meta เป็นช่วงกว้าง ๆ ไม่ใช่จำนวนคนจริง**
   ใช้เทียบขนาดกันเองได้ อย่าเอาไปคำนวณ reach
2. **Meta แถม interest กว้าง ๆ ชุดเดิมมาท้ายผลทุกคำค้น** ("Facebook access (mobile)",
   "Frequent Travelers", "Friends of people with birthdays") — พวกนี้**ไม่เกี่ยวกับสินค้า**
   หน้าเว็บติดป้าย "กว้างทั่วไป" และดันลงล่างให้แล้ว แต่ถ้า user ถามถึง ให้อธิบายตรง ๆ

### โควตา

`search_interest` และ `suggest_interest` จำกัด **200 ครั้ง/ชั่วโมงต่อ tool** ที่หลังบ้าน ·
"ให้ Claude หาให้" หนึ่งครั้ง = 6 ครั้ง · บอก user ถ้าเขาถามว่ากดรัว ๆ ได้ไหม.

## ตอบในแชทเลย (ไม่ต้อง publish) เมื่อไหร่

user ถามคำถามเดียวจบ เช่น "interest กาแฟมี id อะไรบ้าง" / "ขยายจาก interest นี้ได้อะไรอีก" →
**ยิง `search_interest` / `suggest_interest` แล้วตอบเป็นตารางในแชทได้เลย ไม่ต้องทำหน้า**
แล้วค่อยเสนอท้ายว่า "อยากได้เป็นหน้าเครื่องมือไว้ใช้เองไหม" หนึ่งบรรทัด.

publish หน้าให้เมื่อ: user ขอเครื่องมือ/หน้า/ที่ค้นเอง · ต้องค้นหลายรอบ · อยากเก็บเป็นชุด ·
หรือเขาบอกว่าจะใช้บ่อย.

## หลัง publish

ส่งลิงก์ + สามบรรทัด: หน้านี้ใช้ connector ของเขาเอง · ตัวเลขเป็นค่าประมาณ ·
**แชร์ต่อไม่ได้ ใครอยากใช้ต้องมีหน้าของตัวเอง**

อย่าเปิดหน้าเทสเอง (เปิดจากฝั่งเรา `claude.use()` คืน `null` เสมอ ไม่ได้แปลว่าหน้าพัง)
ถ้า user บอกว่าอะไรไม่ทำงาน ให้ไล่ตาม `references/publish-manifest.md` หัวข้อ "แก้ปัญหา".
