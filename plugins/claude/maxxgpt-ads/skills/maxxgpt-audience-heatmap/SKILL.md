# MaxxGPT — Audience Heatmap (แผนที่ความร้อนกลุ่มเป้าหมาย)

ส่งมอบ **หน้าเว็บส่วนตัวของ user** (Artifact) ที่เปิดดูเองได้ตลอดว่าเงินที่ยิงไป
กลุ่มอายุ×เพศ ไหนได้ผลถูกที่สุด แทนที่จะตอบเป็นตารางในแชทครั้งเดียวแล้วหาย.
รอบเดียวจบ — user เก็บลิงก์ไว้เปิดใช้ได้เรื่อย ๆ ข้อมูลดึงสดทุกครั้งที่เปิด.

> ## 🔴 กฎเหล็ก (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error
>    `The connector's server isn't responding.` ที่ดูเหมือน server พังทั้งที่ไม่ใช่
> 2. **ห้าม publish โดยไม่ส่ง `capabilities`** — manifest ไม่ได้อยู่ในไฟล์ HTML แต่เป็น
>    argument ของตอน publish · ลืมส่ง = `claude.use()` คืน `null` ทุกตัว หน้าจะเปิดได้แต่
>    **ตารางไม่ขึ้นเลย** ปุ่มแนะนำ ad set กดแล้วเงียบ **โดยไม่มี error ให้เห็น**
> 3. **ห้ามฮาร์ดโค้ดชื่อ connector และห้ามใส่ชื่อสำรอง** — ชื่อเป็นของ user แต่ละคน
>    ต้อง**ค้นหาจาก tool ที่ connector นั้นมี** ตามขั้น 1 แล้วประกาศ **ชื่อเดียวที่หาเจอ** ·
>    ใส่ชื่อเผื่อไว้ = กล่องขออนุญาตเด้งถามซ้ำทุกครั้งที่เปิดหน้า
> 4. **ต้องยิง `get_dashboard_demographics` จริงอย่างน้อยหนึ่งครั้งก่อน publish** — กฎของ
>    artifact คือห้าม publish หน้าที่เรียก connector tool โดยไม่เคยเห็น request/response
>    จริงในเซสชันนั้น · ยิง `get_account_info` ด้วยอีกตัวเพราะหน้าเรียกสองตัว
> 5. **หน้านี้แชร์ต่อให้คนอื่นไม่ได้** — capability `mcp` ปิดการแชร์สาธารณะไว้ และ tool ทุกตัว
>    ถูกเรียกด้วยเครดิตของ *คนเปิดหน้า* → ใครอยากใช้ ต้อง publish หน้าของตัวเอง **ห้ามบอก user
>    ว่าส่งลิงก์นี้ให้ลูกค้าหรือทีมได้**
> 6. **บัญชีโฆษณา · เพจ (MaxxGPT V4)** — ไม่ส่งอะไร = tool ใช้บัญชี/เพจที่ user เลือกไว้ในเว็บ MaxxGPT (กรณีปกติ) ·
>    ทุก tool รับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ) ·
>    id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
>    user มีหลายบัญชีแล้วไม่ระบุ → ใช้ค่า default ไปก่อน แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (ทุกคำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง)
>
>    **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
>    `reason: OVER_QUOTA` = ผูกบัญชี/เพจเกินโควตาแพ็กเกจ (`ad_account_quota.linked > max_ad_accounts`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
>    `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์นี้ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้
> 7. **ช่วงเวลามีแค่ 3 ค่า** — 7 วันล่าสุด / เมื่อวาน / วันนี้ · tool ไม่รับพารามิเตอร์วันที่
>    **ห้ามสัญญากับ user ว่าเลือกช่วงเองได้** (ถ้าเขาอยากได้ช่วงอื่น ให้ใช้สกิลรายงานตัวอื่นแทน)
> 8. **เจอหน้าเดิมที่ทำงานแทบเหมือนกัน = ต้องถามก่อนเสมอ** (ขั้น 3) ว่าจะอัปเดตตัวเดิม
>    หรือสร้างใหม่ · **ห้ามตัดสินใจแทน** — สร้างใหม่ = ลิงก์ที่เขาแปะไว้ที่อื่นชี้ไปหน้าเก่า

## ผังการทำงาน · Flow

```
1  หา connector ตัวจริง ──► ชื่อที่ user ตั้งไว้ (ห้ามเดา)
2  ยิงของจริง 2 ตัว ทีละตัว ──► get_dashboard_demographics แล้ว get_account_info
3  เคยมีหน้าแบบนี้อยู่แล้วไหม ──► มี = 🔴 ถามก่อน (อัปเดตตัวเดิม / สร้างใหม่)
                                └─ ไม่มี = publish ใหม่ได้เลย
4  publish พร้อม capabilities manifest ──► ส่งลิงก์ + อธิบายวิธีอ่านสั้น ๆ
```

### ขั้น 1 · หา connector ตัวจริง (ห้ามข้าม)

**ชื่อ connector เป็นของ user แต่ละคน** — บางคนตั้งว่า `MaxxGPT MCP` บางคน `MaxxGPT`
บางคนตั้งเป็นชื่อบริษัทตัวเอง และ artifact รับได้เฉพาะ **ชื่อที่แสดง** เท่านั้น
(ไม่รับ id ไม่รับ URL — ในหน้าเว็บก็มองไม่เห็น URL เช่นกัน เป็นข้อกำหนดถาวรของ runtime)

> ### 🔴 ต้องเป็น **claude.ai connector** เท่านั้น — ของที่ปลั๊กอินประกาศใช้ไม่ได้
> ปลั๊กอิน `maxxgpt-ads` ประกาศ MCP server ชื่อ **`maxxgpt`** ไว้ใน `.mcp.json` ·
> อันนั้นเป็น **local MCP server ของ Claude Code** — ใช้ยิง tool ในแชทได้ แต่
> **หน้า artifact เรียกไม่ได้** (สเปกระบุว่า `server` รับเฉพาะ claude.ai connector ·
> local MCP server ไม่นับ) · **ชื่อสองอันนี้ไม่ต้องตรงกันและมักไม่ตรง**
>
> ⚠️ **ยิง tool ในแชทได้ ไม่ได้แปลว่าจะ publish ได้** — ถ้าเขามีแต่ server จากปลั๊กอิน
> สกิลจะทำงานในแชทได้ปกติแต่หน้าที่ publish ออกไปจะขึ้น "ยังเชื่อมต่อ MaxxGPT ไม่ได้"
> → เจอแบบนี้ **ห้าม publish** ให้บอกเขาไปเพิ่ม connector ที่ claude.ai → Settings →
> Connectors ด้วย URL `https://mcp.maxxgpt.ai/mcp` ก่อน แล้วค่อยกลับมาเรียกสกิลใหม่

1. เรียกสกิล **`artifact-capabilities`** — มันจะพิมพ์รายชื่อ **claude.ai connector** ของ
   เซสชันนี้พร้อมชื่อที่แสดงจริง คู่กับ id ที่ใช้ใน tool name (`mcp__<id>__<tool>`) ·
   **connector ที่ใช้ได้มีแค่ที่อยู่ในรายการนี้**
2. **จับคู่จากความสามารถ ไม่ใช่จากชื่อ** — หา connector ที่มีทั้ง
   `get_dashboard_demographics` และ `get_account_info` · ตัวที่มีสองตัวนี้คือตัวที่ใช่
   ไม่ว่าจะชื่ออะไร (ชื่อที่มีคำว่า MaxxGPT แต่ไม่มีสอง tool นี้ = ไม่ใช่ อย่าหยิบมาใช้)
3. เจอหลายตัวที่เข้าเกณฑ์ → ถามผู้ใช้ว่าจะใช้ตัวไหน บอกชื่อที่เจอทั้งหมด
   และบอก URL ข้างบนให้เขาไปเทียบเอง **ห้ามเดา ห้ามประกาศทั้งหมด**
4. ไม่เจอเลย → แจ้ง user ให้ไปต่อ connector ที่ URL ข้างบน แล้วหยุด **ห้าม publish ทิ้งไว้**

ผลของขั้นนี้ = **ชื่อเดียว** ที่จะเป็น `server` ตัวเดียวใน manifest ตอน publish

### ขั้น 2 · ยิงของจริง (ทีละตัว)

เรียก **`get_dashboard_demographics`** (ไม่มี argument) แล้วรอให้จบ **ค่อย** เรียก
**`get_account_info`** — สองอย่าง:
- ยืนยันว่า connector ตอบจริง ไม่ใช่แค่ปรากฏในรายการ
- ทำให้เข้าเงื่อนไข "เคยเห็น response จริง" ของทั้งสอง tool ที่หน้าเรียก

ผ่านเมื่อได้:
```
get_dashboard_demographics  { status:200, success:true,
                              d7_age_gender / yesterday_age_gender / today_age_gender
                              : { fields:[27 ชื่อคอลัมน์], rows:[[...]] } }
get_account_info            { status:200, success:true,
                              ad_account:{id:"act_…", account_id, name, currency, …},
                              page:{id, name} }
```
ได้ error = แจ้ง user แล้วหยุด.

> ⚠️ **payload หนัก** — `get_dashboard_demographics` คืนตาราง 27 คอลัมน์ × 3 ช่วงเวลา
> ยิงหนึ่งครั้งพอสำหรับการยืนยัน **อย่ายิงซ้ำเพื่อไล่ดูตัวเลข** ปล่อยให้หน้าเว็บดึงเอง

### ขั้น 3 · เคย publish ให้เขาแล้วหรือยัง — 🔴 **เจอของเดิมต้องถามก่อน**

ใช้ `Artifact action:"list"` แล้วมองหา **หน้าที่ทำงานแทบเหมือนกัน** — ไม่ใช่แค่ชื่อตรงเป๊ะ
นับว่า "แทบเหมือนกัน" เมื่อชื่อหรือคำอธิบายสื่อถึงแผนที่ความร้อน/กลุ่มเป้าหมายอายุ×เพศ เช่น
`แผนที่ความร้อนกลุ่มเป้าหมาย` · `Audience Heatmap` · `heatmap อายุเพศ` · `กลุ่มเป้าหมาย Meta`
ชื่ออื่นที่ user ตั้งเองแต่เนื้อหาเป็นเรื่องเดียวกัน ก็ให้นับด้วย.

**ไม่เจอ** → publish ใหม่ได้เลย พร้อม `favicon: "🎯"` ไม่ต้องถาม

**เจอ (ตัวเดียวหรือหลายตัว)** → **หยุดแล้วถาม user ก่อน ห้ามเลือกเอง**
ใช้ `AskUserQuestion` บอกไปว่าเจอหน้าอะไรบ้าง (ชื่อ + วันที่แก้ล่าสุด) แล้วให้เลือก:

| ตัวเลือก | ผลที่ตามมา — **ต้องบอก user ให้ครบ** |
|---|---|
| **อัปเดตตัวเดิม** (ค่าที่ควรแนะนำ) | ลิงก์เดิมไม่เปลี่ยน · คนที่เปิดหน้านี้ค้างอยู่จะเห็นเวอร์ชันใหม่ทันที |
| **สร้างใหม่แยกอีกหน้า** | ได้ลิงก์ใหม่ · ของเดิมยังอยู่ที่ลิงก์เก่า ไม่ได้ถูกลบ · ลิงก์ที่เขาแปะไว้ที่อื่นยังชี้ไปตัวเก่า |

> หน้านี้ **ไม่มี `db`** จึงไม่มีข้อมูลที่ user บันทึกไว้ให้หาย — ต่างจาก interest-explorer
> ที่สร้างใหม่แล้วชุดที่บันทึกไว้ไม่ตามมา · ที่นี่ประเด็นเดียวคือ **ลิงก์เปลี่ยน**

เจอหลายตัวแล้วเขาเลือก "อัปเดตตัวเดิม" → ถามต่อว่าอันไหน (อย่าเดา)

**ลงมือตามที่เขาเลือก**

| เลือก | ทำอะไร |
|---|---|
| อัปเดตตัวเดิม | `action:"read"` ที่ URL นั้น**ก่อนเสมอ** (บังคับ ไม่งั้น publish จะถูกปฏิเสธ) แล้ว publish ด้วย `url` เดิม · **ห้ามใส่ `favicon`** · ห้ามใส่ `contract` |
| สร้างใหม่ | publish โดย**ไม่ใส่** `url` · ใส่ `favicon: "🎯"` · ตอนส่งลิงก์ให้ย้ำอีกครั้งว่าอันเก่ายังอยู่ที่ลิงก์เดิม |

### ขั้น 4 · publish

ไฟล์: `assets/audience-heatmap.html` — **publish ทั้งไฟล์ตามที่เป็น ห้ามแก้เนื้อไฟล์**
manifest ฉบับเต็มและเหตุผลอยู่ใน `references/publish-manifest.md`

```
capabilities:
{
  "mcp": { "servers": [
    { "server": "<ชื่อที่เจอในขั้น 1 — ตัวเดียว>",
      "tools": ["get_dashboard_demographics", "get_account_info"] }
  ] },
  "sample": {}
}
```

> ### 🔴 ประกาศ connector **ชื่อเดียว** เท่านั้น
> ห้ามใส่ชื่อสำรองเผื่อไว้เด็ดขาด — หน้าขออนุญาตของ Claude พิมพ์**หนึ่งแถวต่อหนึ่งชื่อที่ประกาศ**
> ชื่อที่ user ไม่มีจะขึ้นว่า *"No matching connector found"* พร้อมปุ่ม *Add custom* และทำให้
> กล่องขออนุญาต**เด้งถามซ้ำทุกครั้งที่เปิดหน้า** · ชื่อเดียวที่ตรง = ถามครั้งเดียวจบ

- **ห้ามลืม `get_account_info`** — ลืมแล้วแถบบัญชีกับปุ่มเปิดบัญชี/เปิดเพจ **ไม่โผล่เงียบ ๆ**
  ส่วน heatmap ยังทำงานปกติ (ออกแบบให้ไม่ล้มตามกัน) → หา bug ยากมาก
- `contract` **ห้ามส่ง** ตอน update (ปล่อยให้ carry forward) · publish ใหม่ก็ไม่ต้องส่ง
- `description` สั้น ๆ: "ดูว่ากลุ่มอายุ×เพศ ไหนได้ผลลัพธ์ถูกที่สุด เพื่อตั้งกลุ่มเป้าหมายของ ad set"

## หน้าที่ได้ ทำอะไรได้บ้าง (ใช้เขียนสรุปให้ user)

### 🔴 สามเรื่องที่ต้องเตือน user เสมอ

1. **ช่องที่ขึ้นลายทาง "ข้อมูลน้อย" ห้ามเอาไปตัดสินใจ** — เกณฑ์ของหน้าคือต้องมีผลลัพธ์
   อย่างน้อย **3 รายการ** และใช้จ่าย **≥ ฿100** ถึงจะนับ · ช่องที่ไม่ผ่านจะไม่ถูกคิดใน
   สเกลสีและไม่ถูกส่งให้ Claude สรุป (ใส่กติกาไว้ในคำสั่งแล้ว)
2. **"วันนี้" ยังไม่ครบวัน** ตัวเลขจะเพิ่มขึ้นเรื่อย ๆ อย่าฟันธงจากช่วงนี้
3. **สีเทียบกันเองภายในช่วงเวลาที่เลือกเท่านั้น** ไม่ใช่ค่ามาตรฐานของอุตสาหกรรม —
   สลับช่วงเวลาแล้วสีของช่องเดิมเปลี่ยนได้ เพราะฐานเทียบเปลี่ยน

## ตอบในแชทเลย (ไม่ต้อง publish) เมื่อไหร่

user ถามคำถามเดียวจบ เช่น "ผู้หญิงหรือผู้ชายถูกกว่า" / "อายุไหนต้นทุนต่อแชทต่ำสุด" →
**ยิง `get_dashboard_demographics` แล้วตอบเป็นตารางในแชทได้เลย ไม่ต้องทำหน้า**
แล้วค่อยเสนอท้ายว่า "อยากได้เป็นหน้าไว้เปิดดูเองไหม" หนึ่งบรรทัด.

publish หน้าให้เมื่อ: user ขอเครื่องมือ/หน้า/แดชบอร์ด · ต้องดูซ้ำหลายรอบ ·
อยากสลับเมตริกไปมาเอง · หรือเขาบอกว่าจะใช้บ่อย.

## หลัง publish

ส่งลิงก์ + สามบรรทัด: หน้านี้ใช้ connector ของเขาเอง ดึงสดทุกครั้งที่เปิด ·
ช่องลายทาง = ข้อมูลน้อย อย่าใช้ตัดสินใจ · **แชร์ต่อไม่ได้ ใครอยากใช้ต้องมีหน้าของตัวเอง**

อย่าเปิดหน้าเทสเอง (เปิดจากฝั่งเรา `claude.use()` คืน `null` เสมอ ไม่ได้แปลว่าหน้าพัง)
ถ้า user บอกว่าอะไรไม่ทำงาน ให้ไล่ตาม `references/publish-manifest.md` หัวข้อ "แก้ปัญหา".
