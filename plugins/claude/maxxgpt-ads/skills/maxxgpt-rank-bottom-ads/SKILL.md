# MaxxGPT — Bottom Rank Ads (คัดแยก ปิด / เฝ้าดู / เก็บไว้)

พา user จาก "ตัวไหนควรปิด" ไปจนได้ **การคัดแยกเป็น 3 ถัง** ของโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก ในบัญชีที่ผูกกับ MaxxGPT
แล้วอยู่ต่อเพื่อตอบคำถามเจาะลึกจากข้อมูลชุดเดียวกัน

Sort every ad into stop / watch / keep — then stay for follow-ups.

> ## 🔴 กฎเหล็ก 6 ข้อ (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error `The connector's server isn't
>    responding.` ที่**ดูเหมือน server พังทั้งที่ไม่ใช่** · เจอ error นี้ให้สงสัยวิธีเรียกของตัวเองก่อน
> 2. **เป็นงาน async** — ยิง tool ได้ `job_id` แล้วต้อง **poll `get_job` เองจนจบ** ตาม
>    `poll_hint.poll_after_seconds` · **ห้ามจบ turn คืนงานให้ user ระหว่างรอ** ·
>    **มี `job_id` มาให้แล้ว = ข้ามการยิง tool ไปเลย** (ดู § ทางลัดข้างล่าง)
> 3. **ห้ามเทข้อมูลดิบทั้งก้อนลงแชท** — คำนวณยอดรวมจากข้อมูลเต็ม แล้ว**พิมพ์ตารางแค่ 10 แถวต่อระดับ**
>    เสมอ (ดู § 5) · ข้อมูลเต็มยังอยู่กับเราไว้ตอบคำถามต่อ
> 4. **ตัวเลขทุกตัวต้องมาจาก `data` จริงเท่านั้น** — คีย์ไหนไม่มีก็ตัดคอลัมน์นั้นทิ้ง
>    **ห้ามเดา ห้ามเติมค่าที่ระบบไม่ได้ส่งมา ห้ามคำนวณเมตริกใหม่ที่ปลายทางไม่ได้ให้**
> 5. **การจัดกลุ่ม "ควรปิด / เฝ้าดู / ทำได้ดี" เป็นของปลายทาง ห้ามตัดสินเอง** — เราแสดงและอธิบาย
>    ตามถังที่ระบบจัดมา · **สกิลนี้ไม่ปิดโฆษณาให้ ไม่แก้งบให้** ได้แค่บอกว่าตัวไหนอยู่ถังไหน ·
>    🔴 **นี่คือการคัดแยก *ทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก* ไม่ใช่ลิสต์ตัวที่แย่** (โฆษณาเป้าอื่นไม่อยู่ในถังใดเลย) — ถัง `Keep` คือตัวที่ทำได้ดี
>    **ห้ามเรียกทั้งชุดว่า "โฆษณาที่ทำได้แย่" และห้ามบอกว่าของในถัง Keep เป็นตัวไม่ดี**
> 6. **ห้ามสร้าง widget / ฟอร์ม HTML / การ์ด UI เด็ดขาด** — ห้ามเรียก tool แสดงวิชวลทุกตัว
>    (`visualize` · `show_widget` · `render-ui` · Artifact) และ**ห้ามเขียน HTML/ฟอร์มเอง**
>    ถามด้วย **tool `AskUserQuestion` (ปุ่มตัวเลือก)** เท่านั้น · เรียกไม่ได้จริง ๆ =
>    **ถามเป็นข้อความแบบเลขข้อ (1 / 2 / 3) แล้วหยุดรอ user ตอบ** ห้ามเดาเองแล้วยิงต่อ

> tool ที่ทำงานกับบัญชีโฆษณารับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ · `get_job` / `search_interest` / `suggest_interest` ไม่มีสอง argument นี้) ·
> id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
> user มีหลายบัญชีแล้วไม่ระบุ → ใช้ค่า default ไปก่อน แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (คำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง · ยกเว้น `get_job` · `get_dashboard_demographics` แนบตั้งแต่ MCP 1.23.2) · ส่ง `ad_account_id` ให้ tool ใด ต้องส่งค่าเดียวกันให้ `get_account_info` ด้วย และเรียก `get_account_info` ใหม่เมื่อเปลี่ยนบัญชี (สกุลเงิน/โซนเวลาเป็นของบัญชีนั้น)
>
> **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
> `reason: OVER_QUOTA` = ผูกบัญชีโฆษณาหรือเพจเกินโควตาแพ็กเกจ (`ad_account_quota.over_quota` / `page_quota.over_quota`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
> `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์ (tool ที่สกิลนี้ใช้ยังไม่มีตัวไหนตอบรหัสนี้) · `SUBSCRIPTION_EXPIRED` (403) = แพ็กเกจหมดอายุ → ให้ต่ออายุในเว็บ MaxxGPT (ล็อกอินใหม่ไม่ช่วย) · `NO_SESSION` / `USER_NOT_FOUND` (401) = connector ไม่รู้จักผู้ใช้ → ให้เชื่อมต่อ connector MaxxGPT ใหม่ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้

## ⚡ ทางลัด · มี `job_id` มาแล้ว = ข้ามไปวิเคราะห์เลย

**ถ้าข้อความของ user มี `job_id` ติดมา ให้ข้ามขั้น 1-2 ทั้งหมด** — ไม่ต้องถามอะไรเพิ่ม
**ไม่ต้องยิง `analysis_bad_<metric>` ใหม่** (ยิงใหม่ = เสียเวลา 1-5 นาที + เปลืองโควตา + อาจชน `JOB_ALREADY_RUNNING`)

**นับว่า "มี job_id" เมื่อ:** user พิมพ์/วางมาตรง ๆ (`job_id=…` · `[job_id=…]` · "ดูผลจากจ็อบ …" ·
วาง id ดิบ ๆ มาพร้อมบอกให้วิเคราะห์) · สกิลอื่นหรือเทิร์นก่อนหน้าส่งต่อมาให้ · งานตั้งเวลา/ระบบภายนอกแนบมา

```
job_id ที่ได้มา ──► get_job(job_id) ──► poll จน success ──► เช็คลายเซ็นข้อมูล ──► ตัด+แสดงผล
```

### ทำตามนี้

1. **`get_job(job_id)` ทันที** — ไม่ต้องยิง tool วิเคราะห์ · `processing` ก็ poll ต่อตามขั้น 3 ปกติ
2. **`get_account_info`** ยังต้องเรียก (1 ครั้งต่อ session ต่อบัญชี) เพื่อเอา **สกุลเงิน + ชื่อบัญชี** ไปใส่หัวเรื่อง —
   แต่เรียก**ตอนไหนก็ได้** ไม่ต้องรอก่อน get_job
3. **เช็คว่าเป็นข้อมูลของหัวข้อนี้จริงไหม** — `function_name` ต้องเป็น `badInbox` / `badLead` / `badPurchase` · ไม่มีค่านี้ค่อยดูรูปร่าง: `data.Ad` ต้องเป็น **object** `{Close, Watch, Keep}` ไม่ใช่ array
   → **ตรง** = วิเคราะห์ต่อตามขั้น 4-5 ปกติ
   → **ไม่ตรง** = ห้ามฝืนแปลง **บอก user ว่า job นี้เป็นผลของหัวข้ออื่น** แล้วชี้สกิลที่ตรงจากตารางข้างล่าง
     (ถ้า user ยืนยันให้ดูต่อ = แสดงเท่าที่คีย์จริงมี แล้วเขียนในหมายเหตุว่าไม่ใช่หัวข้อของสกิลนี้)
4. **ช่วงวันที่และบัญชีของ job: `get_job` ไม่ได้คืนมาด้วย** — 🔴 **ห้ามเดา ห้ามใส่ช่วงมั่ว ๆ ในหัวเรื่อง**
   · user บอกช่วงมาด้วย = ใช้ตามนั้น · ไม่บอก = เว้นช่วงวันที่ในหัวเรื่องไว้ แล้วเขียนในหมายเหตุว่า
   "ผลชุดนี้มาจาก job ที่ส่งมา — ระบบไม่ได้แนบช่วงวันที่มาด้วย" ·
   ชื่อบัญชีในหัวเรื่องคือบัญชีจาก `get_account_info` ตอนนี้ — เขียนในหมายเหตุด้วยว่า **ไม่ยืนยันว่า job นี้รันกับบัญชีนั้น**
5. `code: JOB_NOT_FOUND` = **job_id ผิด เป็นของ user คนอื่น หรือเป็น job_id จากระบบเดิมก่อน V4** (job ผูกกับ login) →
   บอกตรง ๆ แล้วเสนอรันใหม่ตามขั้น 1-2 ปกติ · **ห้าม poll ซ้ำ** (`poll_hint.poll_after_seconds` = 0)
6. `job_status: failed` = งานเก่าล้มไปแล้ว → อ่าน `data.error` ตามขั้น 3 ก่อนเสนอรันใหม่ · `data` ว่าง `{}` = ช่วงนั้นไม่มีข้อมูล ไม่ใช่ error ·
   `job_status: success` แต่ `data` เป็น `null` = ผลหมดอายุแล้ว (ระบบเก็บผล 7 วัน) → เสนอรันใหม่

### ตารางลายเซ็น — job_id นี้เป็นของหัวข้อไหน

**ดู `function_name` ก่อนเสมอ** — `get_job` คืนค่านี้มาด้วย และใช้ได้แม้ `data` เป็น `{}`

| `function_name` | หัวข้อ | สกิลที่ควรใช้ |
|---|---|---|
| `badInbox` · `badLead` · `badPurchase` | Bottom Rank (วัดด้วย inbox / lead / purchase) | `maxxgpt-rank-bottom-ads` |
| `topStar` | Rising Stars | `maxxgpt-rank-rising-stars` |
| `topAware` | Audience Growth | `maxxgpt-rank-audience-growth` |
| `goodInbox` · `goodLead` · `goodPurchase` · `goodROAS` | Top Rank (วัดด้วย inbox / lead / purchase / roas) | `maxxgpt-rank-top-ads` |
| `videoAdsAnalysis` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| `postEngagement` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| `messageAnalysis` | ทักแชท | `maxxgpt-analysis-message` |
| `leadAdsAnalysis` | ลีด | `maxxgpt-analysis-leads` |
| `purchaseAnalysisMETA` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| `purchaseAnalysisCPAS` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `resultOverAll` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |
| `CtrCpmFrq` | Ad Metric Benchmark (สเต็ป 2) | `maxxgpt-ad-metric-benchmark` |
| `exportAds` | รายงานโฆษณาแบบดิบ | `maxxgpt-export-report` |
| `recomendedDashboard` | Ad Spotlight (ผลจริงอ่านจาก `spotlight_get`) | `maxxgpt-ad-spotlight` |

**ไม่มี `function_name` ในคำตอบ** = ใช้ลายเซ็นใน `data` แทน:

| ลายเซ็นใน `data` | หัวข้อ | สกิลที่ควรใช้ |
|---|---|---|
| `Ad` เป็น **object** `{Close,Watch,Keep}` | Bottom Rank | `maxxgpt-rank-bottom-ads` |
| แถวมี `Score` + `CPC` · **ไม่มี `CPM`** และไม่มีคอลัมน์ผลลัพธ์ | Rising Stars | `maxxgpt-rank-rising-stars` |
| แถวมี `Score` + `Reach` + `Frequency` + `CPM` + `CPC` | Audience Growth | `maxxgpt-rank-audience-growth` |
| แถวมี `Score` + `CPM` · ไม่มี `Reach`/`CPC` (`Cost_per_*` `per` ตัวเล็ก มีเฉพาะเมตริก inbox / lead) | Top Rank | `maxxgpt-rank-top-ads` |
| แถวมี `Video_plays` + `Completion_Rate` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| แถวมี `Post_Engagement` + `post_engagement_rate` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| แถวมี `Inbox` + `MSS_VIEW` + `Cost_Per_Inbox` (`Per` ตัวใหญ่) | ทักแชท | `maxxgpt-analysis-message` |
| แถวมี `Lead` + `Cost_per_lead` | ลีด | `maxxgpt-analysis-leads` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **และ** มีคีย์ `Age`/`Gender` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **แต่ไม่มี** คีย์ `Age`/`Gender` และไม่มี `Score` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `data` มีคีย์ `OV` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |
| `data` มีบล็อก `CTR`/`CPM`/`FRQ` + `*_AD` | Ad Metric Benchmark (สเต็ป 2) | `maxxgpt-ad-metric-benchmark` |

⚠️ `purchase_meta` กับ `purchase_cpas` คอลัมน์เหมือนกันเป๊ะ ถ้าไม่มี `function_name` จะแยกได้แค่จากคีย์ `Age`/`Gender` —
**ถ้าไม่มั่นใจให้บอก user ตรง ๆ ว่าเดาว่าเป็นหัวข้อไหน แล้วให้ยืนยัน** อย่าเงียบแล้วเดา

## ผังการทำงาน · Flow

```
ทางลัด · มี job_id ส่งมาให้แล้ว :  get_job(job_id) → poll จน success → ข้ามไปขั้น 4 เลย
ทางปกติ · ไม่มี job_id          :  0 → 1 → 2 → 3 → 4 → 5

0  get_account_info                      รู้ชื่อบัญชี + สกุลเงิน + โซนเวลา
1  ถามเมตริก + ช่วงเวลา + spend ด้วย AskUserQuestion  ข้ามได้ถ้า user บอกมาแล้ว
2  ยิง tool ตาม § ขั้น 2                   ได้ { job_id, code }
3  วน get_job จน job_status = success     ตาม poll_hint · ห้ามจบ turn ระหว่างรอ
4  ตัดข้อมูล + คำนวณยอดรวม
5  พิมพ์สรุป + ตาราง markdown             อยู่ต่อเพื่อตอบคำถามจากข้อมูลชุดเดิม
```

### ขั้น 0 · รู้ก่อนว่าบัญชีไหน

เรียก `get_account_info` **หนึ่งครั้งต่อ session ต่อบัญชี** เก็บ ชื่อบัญชี / `act_…` / สกุลเงิน / โซนเวลา ไว้ใช้ทุกขั้น

tool คืน `{ success, ad_account, page }` — ที่ต้องหยิบไปใช้:

| คีย์ใน `ad_account` | เอาไปใช้ตรงไหน | หมายเหตุ |
|---|---|---|
| `name` | ชื่อบัญชีในหัวเรื่อง | ชื่อบัญชีโฆษณา |
| `id` | วงเล็บต่อท้ายชื่อบัญชี | มี prefix `act_` มาแล้ว (`account_id` คือตัวไม่มี prefix) |
| `currency` | หน่วยเงินต่อท้ายตัวเลขเงินในตาราง | เช่น `THB` — `null` ได้ |
| `timezone_name` | ใช้คำนวณ "วันนี้" ตอนแปลงช่วงเวลา | เช่น `Asia/Bangkok` |
| `account_status` | เตือนไว้ในหมายเหตุถ้าบัญชีมีปัญหา | **เป็นตัวเลข ไม่ใช่ข้อความ** — `1` = ใช้งานได้ · ค่าอื่น (`2`,`3`,`101`,…) = บัญชีมีปัญหา · `null` = MaxxGPT ยังไม่เคยอ่านค่านี้จาก Meta (ไม่ใช่บัญชีมีปัญหา) |
| `synced_at` | รู้ว่า `account_status` / `timezone_name` เก่าแค่ไหน | สองค่านั้นคือค่าที่ MaxxGPT อ่านจาก Meta ล่าสุด ณ เวลานี้ ไม่ใช่ค่าสด — `null` ได้ |

- โซนเวลาใช้คำนวณ **"วันนี้"** ตอนแปลงคำพูดเป็นช่วงวันที่ — หาไม่เจอให้ใช้ `Asia/Bangkok`
- สกุลเงินใช้ต่อท้ายตัวเลขเงินทุกตัว — หาไม่เจอให้เว้นว่าง **ห้ามเดาว่าเป็น THB**
- บัญชีที่ `account_status` ไม่ใช่ `1` ยังดูผลย้อนหลังได้ ทำต่อได้ปกติ (เขียนเตือนไว้ในหมายเหตุ)

### ขั้น 1 · เลือกเมตริก + ช่วงเวลา

**ถ้า user บอกมาครบแล้ว ไม่ต้องถามอะไรอีก** — บอกหนึ่งบรรทัดว่าใช้อะไร แล้วยิงต่อ

| user พูดมาแบบ | ทำอะไร |
|---|---|
| บอกครบ | ไม่ต้องถาม → ยิงเลย + บอกว่าใช้เมตริก/ช่วงไหน |
| บอกช่วง แต่ไม่บอกเมตริก | **ถ้าเดาเมตริกจากบริบทได้ให้เดา** (พูดถึงแชท = `inbox` · ลีด = `lead` · ยอดขาย = `purchase`) แล้ว**บอกว่าเลือกให้** · เดาไม่ได้ = ถามด้วย `AskUserQuestion` |
| **เคยรู้ช่วงเวลาแล้วใน session นี้** (รวมช่วงที่ได้จากสกิลวิเคราะห์ตัวอื่น) | ใช้ช่วงเดิมต่อ ยิงเลย + บอกว่าใช้ช่วงเดิม |
| ไม่บอกอะไรเลย | ถามด้วย `AskUserQuestion` |

**ห้ามถามช่วงเวลาซ้ำ** ถ้า session นี้เคยได้ช่วงเวลามาแล้ว — ใช้ค่าเดิมต่อ แล้วบอกว่ากำลังใช้ช่วงไหน ·
user เปลี่ยนทีหลังได้โดยบอกมาในแชท (ไม่ต้องถามใหม่ด้วยปุ่ม)

**`spend` (ยอดใช้จ่ายขั้นต่ำ)** = ตัดแถวเล็ก ๆ ที่เป็น noise ออกก่อนคัดแยก · เป็น**ตัวเลข** ไม่ใช่สตริง ·
user ไม่ได้ระบุ = ส่ง `0` (ไม่กรอง) ·
**ตั้ง `spend` แล้วต้องเขียนในหมายเหตุว่ากรองที่เท่าไร** ไม่งั้น user งงว่าทำไมแอดหาย

**ถามยังไง — ใช้ tool `AskUserQuestion` (ปุ่มตัวเลือก) เสมอ · ห้ามสร้าง widget/ฟอร์ม HTML · ห้ามพิมพ์คำถามเปล่า ๆ:**
สเปกคำถาม/ตัวเลือกอยู่ใน [references/output-format.md](references/output-format.md) § ถาม — **ถามทุกอย่างที่ยังไม่รู้ในการเรียกครั้งเดียว** ·
ที่รู้แล้วห้ามถามซ้ำ · user กด "Other" พิมพ์ช่วงเองได้ → แปลงเป็นวันที่ตามตารางในไฟล์นั้น

### ขั้น 2 · ยิง tool

| `metric` | tool | คอลัมน์ผล / ต้นทุน |
|---|---|---|
| `inbox` | `analysis_bad_inbox` | `Inbox` / `Cost_per_Inbox` |
| `lead` | `analysis_bad_lead` | `Lead` / `Cost_per_Lead` |
| `purchase` | `analysis_bad_purchase` | `Purchase` / `Cost_per_Purchase` |

```
<tool ตามตาราง>(date_start="YYYY-MM-DD", date_end="YYYY-MM-DD", spend=<number>)
```

🔴 **หัวข้อนี้ไม่มี `metric=roas`** (ปลายทางไม่มี) — user ขอมาให้บอกตรง ๆ แล้วเสนอ `purchase` แทน

- วันที่เป็น `YYYY-MM-DD` ตามโซนเวลาบัญชี · `date_start ≤ date_end`
- `spend` = ยอดใช้จ่ายขั้นต่ำที่จะเอามาคัดแยก · **เป็นตัวเลข ไม่ใช่สตริง** · `0` = เอาทุกแถว

ผลที่ได้คือ `{ job_id, code }` — **`code` มี 2 แบบที่ต้องแยก:**

| `code` | หมายถึง | ทำอะไรต่อ |
|---|---|---|
| `JOB_CREATED` | เริ่มงานใหม่แล้ว | poll ตามปกติ |
| `JOB_ALREADY_RUNNING` | **มีงานหัวข้อเดียวกันค้างอยู่ — `job_id` ที่ได้เป็นของงานเก่า** | poll ต่อได้ แต่ **ผลเป็นของช่วงวัน/ตัวเลือกที่สั่งไว้รอบก่อน ไม่ใช่ที่เพิ่งขอ** → บอก user ตรง ๆ + เขียนไว้ในหมายเหตุ แล้วเสนอรันใหม่หลังงานเก่าจบ |

> 1 user มีงานของ **tool เดียวกัน** ได้ทีละ 1 งาน (คนละ tool รันพร้อมกันได้ แต่เรายังยิงทีละตัวอยู่ดี)

### ขั้น 3 · รอผล (poll)

```
get_job(job_id)  →  { job_status, function_name, progression, data, poll_hint }
```

- `processing` → รอ `poll_hint.poll_after_seconds` วินาที **พิมพ์บรรทัดสั้น ๆ ให้ user เห็นว่ายังทำงานอยู่**
  (เช่น "ยังประมวลผลอยู่ ~40% — เช็คอีกครั้งใน 15 วิ") แล้ว poll ต่อ **ห้ามจบ turn**
- `success` → อ่าน `data` · **`data` อาจมาเป็นสตริง JSON → parse ก่อนใช้**
- `failed` + `data = {"error":"time_out"}` → เกินเพดานเวลา 5 นาที **ห้ามยิงซ้ำทันที**: บอก user ว่าช่วงที่ขอหนักไป
  แล้วเสนอย่นช่วงวัน (30 วัน → 7-14 วัน) ก่อนรันใหม่
- `poll_hint.poll_after_seconds = 0` = หยุด อย่า poll ต่อ
- `failed` ที่ `data.error` เป็นค่าอื่น → **อย่ารันซ้ำเฉย ๆ** ให้อ่านรหัสก่อน: `META_TOKEN_INVALID` = การเชื่อมต่อ Meta หมดอายุ/ถูกยกเลิก →
  ให้ user ต่อ Meta ใหม่ในเว็บ MaxxGPT (รันซ้ำไม่ช่วย) · `META_RATE_LIMITED` = Meta จำกัดคำขอชั่วคราว รอ 2-3 นาทีแล้วค่อยรันใหม่ ·
  `META_PERMISSION_DENIED` = บัญชีที่ต่อไว้ไม่มีสิทธิ์ในบัญชีโฆษณานี้ · รหัสอื่น (`META_ERROR` ฯลฯ) = บอก `data.message` แล้วเสนอรันใหม่
- tool ตอบ error แทน `job_id` → อ่าน `code` ตามกล่อง "รหัสที่ต้องรู้จัก (V4)" ข้างบน · วันที่ผิดรูป (ไม่ใช่ `YYYY-MM-DD`) ถูกปฏิเสธตั้งแต่ตอนเรียก tool
- ได้ข้อความ `Rate limit reached …` → รอตามจำนวนวินาทีที่ข้อความบอก แล้วทำต่อเอง **ห้ามจบ turn** (เริ่มงานได้ 20 ครั้ง/ชั่วโมงต่อ tool)

แล้วพิมพ์เป็นข้อความ + ตาราง markdown ตาม [references/output-format.md](references/output-format.md) § ตอบ

## § 5 · กติกาตัดข้อมูล + วางตาราง (ห้ามข้าม)

| ส่วน | ใส่อะไร |
|---|---|
| สรุปรวม | **คำนวณจากข้อมูลเต็ม** ก่อนตัดแถว |
| ตาราง | **3 ถังตามสิ่งที่ควรทำ: 🔴 ควรปิด (Close) / 🟡 เฝ้าดู (Watch) / 🟢 ทำได้ดี ปล่อยวิ่งต่อ (Keep)** · ใช้ **ระดับโฆษณา (`Ad`)** เพราะเป็นระดับที่ลงมือได้จริง · เขียนใต้ตารางว่า "ระดับ ad set / แคมเปญ ขอดูได้โดยพิมพ์บอก" · **แต่ละถังเอา 10 แถวแรก** ถ้าตัดออกให้เขียน "แสดง 10 จากทั้งหมด N" |
| คอลัมน์ | ชื่อ · `ad_id` · `Spend` · **คอลัมน์ผลของ metric** · **คอลัมน์ต้นทุนของ metric** · `CTR` (หน่วย %) — **ชุดนี้ไม่มี `Score`** อย่าไปหา |
| breakdown | **ไม่มี** — ชุดนี้ไม่มี breakdown อายุ/เพศ/อุปกรณ์ · user อยากได้ให้ชี้ไปสกิลตระกูล `maxxgpt-analysis-*` |
| ปิดท้าย | บรรทัดชวนถามต่อ (ดูด้านล่าง) |

- ระดับโฆษณา ให้ทำชื่อเป็นลิงก์ markdown ไปที่ `post_url` เสมอ (`[ชื่อ](post_url)`) · ไม่มี url = ชื่อเปล่า ๆ
- **ชื่อซ้ำกันได้จริง** (แคมเปญคนละ id ชื่อเดียวกัน · ad set ชื่อ `M-W` หลายตัว · โฆษณาชื่อ `-`) →
  ตารางระดับ ad set/โฆษณา **ให้กำกับด้วย id ของแถวนั้น** (แถวไม่มีชื่อ/ID แคมเปญติดมา — อยากได้ให้ใช้ `maxxgpt-export-report`) และตอบคำถามรายตัวให้แนบ id

**ยอดรวมคำนวณยังไงถึงจะถูก:**

- รวมจากแถวระดับ **Campaign** (ไม่ใช่ Ad เพื่อไม่ให้นับซ้ำ) เว้นแต่ชุดนั้นมีแต่ระดับ Ad
- **ต้นทุนต่อผลรวม = `Spend รวม ÷ ผลรวม`** — **ห้ามเอาต้นทุนต่อผลรายแถวมาเฉลี่ย** (ได้เลขผิด)
- `CTR รวม` = `Clicks รวม × 100 ÷ Impression รวม` ไม่ใช่ค่าเฉลี่ยของ `CTR` รายแถว

**สรุปรวม 4 ช่อง (พิมพ์เป็นตารางเดียว):**

| ช่อง 1 | ช่อง 2 | ช่อง 3 | ช่อง 4 |
|---|---|---|---|
| 🔴 ควรปิด (กี่ตัว) | 🟡 เฝ้าดู (กี่ตัว) | 🟢 ทำได้ดี (กี่ตัว) | ยอดใช้จ่ายที่จมอยู่กับกลุ่ม "ควรปิด" |

**บรรทัดชวนถามต่อ (พิมพ์ปิดท้ายเสมอ):**

```
ถามต่อได้: ขอตารางเต็ม (ทุกแถว) · ดูระดับ ad set / แคมเปญ · เปลี่ยนช่วงเวลา · ดูหัวข้ออื่น
```

**หมายเหตุ (bullet `⚠️` ใต้ตาราง) ใส่เมื่อ:** ช่วงที่ขอรวมวันนี้ · ผลว่าง · ผลมาจาก job เก่า (`JOB_ALREADY_RUNNING`) ·
**ผลมาจาก `job_id` ที่ส่งมาโดยไม่รู้ช่วงวันที่** · บัญชีไม่ ACTIVE ·
**ใช้ `spend` กรอง (บอกว่ากรองที่เท่าไร ไม่งั้น user งงว่าทำไมแอดหาย)**

**ผลว่าง (`data` = `{}` หรือทุกชุดว่าง):** ยังพิมพ์หัวเรื่อง + สรุปตามปกติ แต่บอกเหตุผลแบบภาษาคน:
ถ้า `Close` ว่างแต่ถังอื่นมีของ = **ข่าวดี ไม่ใช่ error** ("ไม่มีตัวที่เข้าข่ายควรปิด") ·
ว่างทั้ง 3 ถัง = ช่วงนี้ไม่มีโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดนี้ (ลองเมตริกอื่น) (ถ้าตั้ง `spend` ไว้ ลองลดลงด้วย)

## 📖 อ่านผลยังไง — สัญญาณของหัวข้อนี้

ส่วนนี้คือสิ่งที่ต้องใช้ตอนเขียนสรุป 2-4 บรรทัดหลังพิมพ์ตาราง · **อ่านก่อนพิมพ์สรุปทุกครั้ง**

> ### 🔴 กติกาของทั้งส่วนนี้ (ผิดข้อไหนคือให้คำแนะนำผิดกับเงินจริงของ user)
>
> 1. **ทุกข้อคือการเทียบ "ภายในชุดที่เพิ่งดึงมา" เท่านั้น** — ไม่ใช่ค่ามาตรฐานอุตสาหกรรม ·
>    **ห้ามพูดว่า "ต่ำกว่ามาตรฐาน" / "ค่าปกติควรอยู่ที่…"** เพราะสกิลนี้ไม่มีค่ามาตรฐานใด ๆ อยู่เลย ·
>    พูดว่า "ต่ำกว่าตัวอื่นในบัญชีช่วงนี้" แทน
> 2. 🔴 **ไม่มีเกณฑ์ตัวเลขตายตัว และจะไม่มี — นี่คือการตัดสินใจของเจ้าของระบบ ไม่ใช่ของที่ยังทำไม่เสร็จ**
>    ค่าที่ "ดี" ขึ้นกับแต่ละบัญชี/ธุรกิจ/สินค้า **ไม่มีสูตรกลาง** →
>    **ห้ามดึงตัวเลขเกณฑ์จากความรู้ทั่วไปหรือจากที่อื่นมาอ้าง** (เช่น "CTR ควรเกิน 1%",
>    "ROAS ต่ำกว่า 3 ถือว่าไม่ผ่าน") **แม้จะฟังดูสมเหตุสมผลก็ห้าม** ·
>    user ถามหา "เกณฑ์มาตรฐานเท่าไร" → **ตอบตรง ๆ ว่าไม่มีสูตรตายตัวเพราะขึ้นกับบัญชี**
>    แล้วเสนอทางที่ทำได้จริง: เทียบกับบัญชีตัวเองด้วย `maxxgpt-ad-metric-benchmark`
>    หรือเทียบกับช่วงเวลาก่อนหน้าของบัญชีเดียวกัน · **ห้ามขอโทษที่ไม่มีเกณฑ์** มันไม่ใช่ข้อบกพร่อง
> 3. **ห้ามสรุปจากแถวที่ `Impression` หรือ `Spend` น้อยมาก** — ตัวเลขยังไม่นิ่ง ·
>    เจอแถวแบบนี้ให้พูดว่า "ยังข้อมูลน้อยเกินจะสรุป" แทนที่จะชม/ตำหนิ
> 4. **พูดเป็น "สัญญาณ + สิ่งที่ควรไปดูต่อ" ไม่ใช่คำสั่ง** — สกิลนี้ไม่ได้เห็นครีเอทีฟ ไม่เห็นหน้าเว็บ
>    ไม่เห็นการตอบแชท จึงบอกได้แค่ว่า *ตัวเลขชี้ไปทางไหน* · **ห้ามฟันธงสาเหตุ**
> 5. **อัตราส่วนที่ปลายทางไม่ได้ให้มา คำนวณเองได้เฉพาะในคำอธิบาย** และต้องกำกับว่าเราคำนวณเอง ·
>    **ห้ามเพิ่มเป็นคอลัมน์ใหม่ในตาราง** (ขัดกฎเหล็กข้อ 4)
> 6. อยากได้ระดับ **High / Medium / Low เทียบค่ากลางของบัญชีจริง ๆ** → นั่นคือสกิล
>    `maxxgpt-ad-metric-benchmark` **ห้ามจัดระดับเองในสกิลนี้**

### สัญญาณที่อ่านได้จากคอลัมน์ของหัวข้อนี้

| เห็นแบบนี้ | อ่านว่า | ไปดูต่อที่ |
|---|---|---|
| ถัง `Close` กินสัดส่วน `Spend` มากเมื่อเทียบกับยอดรวมทั้ง 3 ถัง | **นี่คือเงินที่ปลดล็อกได้มากที่สุด** — ตัวเลขที่ควรพูดเป็นอย่างแรก | เอาไปคุยเรื่องจัดสรรงบใหม่ |
| ในถัง `Close` มีทั้งแถวที่ผล = 0 และแถวที่มีผลแต่แพง | 🔴 **คนละปัญหากัน** — ผล 0 = ไม่ทำงานเลย · มีผลแต่แพง = ทำงานแต่ไม่คุ้ม | แยกพูดสองกลุ่ม อย่าเหมารวม |
| แถวใน `Watch` ที่ `CTR` สูงกว่าตัวอื่นในถังเดียวกัน | **ตัวที่ควรให้เวลาก่อนตัดสิน** — คนยังสนใจอยู่ | รอข้อมูลอีกหน่อยค่อยตัดสิน |
| ถัง `Keep` มีตัวที่ต้นทุนต่อผลถูกที่สุดของบัญชี | **นี่คือของดีของบัญชี** — ต้องพูดถึงด้วย ไม่ใช่พูดแต่ตัวที่ควรปิด | เอาไปเทียบกับ Top Rank |
| `Close` ว่าง แต่ถังอื่นมีของ | **ข่าวดี ไม่ใช่ error** — ช่วงนี้ไม่มีตัวที่เข้าข่ายควรปิด | ชมได้ตามจริง |
| แถวเดียวกันชื่อซ้ำกับแถวอื่น | ต้องอ้าง **`ad_id`** กำกับ ไม่งั้น user ไปปิดผิดตัว | คอลัมน์ `ad_id` ในตาราง |

- 🔴 **นี่คือการคัดแยก *ทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก* ไม่ใช่ลิสต์ตัวที่แย่** — **ห้ามเปิดสรุปด้วยประโยคแบบ
  "โฆษณาที่ทำได้แย่มี N ตัว"** ให้พูดว่า "คัดแยกโฆษณาที่ตั้งเป้าผลลัพธ์นี้ N ตัวออกเป็น 3 กลุ่ม"
- **ถัง `Keep` ว่างทั้งที่มีตัวที่ได้ผล** = มีแถวที่ได้ผลลัพธ์ไม่ถึง 4 แถว ปลายทางเลยจัดแค่ ผล 0 = `Close` · ที่เหลือ = `Watch` — ไม่ได้แปลว่าไม่มีตัวดี
- 🔴 **ถังเป็นของปลายทาง เราไม่ได้ตัดสินเอง** — อธิบายได้ว่า *ทำไมตัวเลขของแถวนั้นถึงดูแย่*
  แต่ **ห้ามพูดว่า "ผมประเมินว่าควรปิด"** และ **สกิลนี้ปิดโฆษณาให้ไม่ได้**
- 🔴 **ถัง `Close` เต็มไปด้วยแถวที่ผล = 0 → คอลัมน์ต้นทุนเป็น 0 ด้วย** —
  **ห้ามอ่านว่า "ต้นทุนถูก"** และห้ามเรียงถังนี้จากต้นทุนน้อยไปมากโดยไม่ตัดแถวผล 0 ออกก่อน
- **แถวที่ `Spend` น้อยมากในถัง `Close`** = ยังข้อมูลน้อยเกินจะสรุป ไม่ใช่ตัวที่ต้องรีบปิด — พูดแยกออกมา

**เขียนสรุปยังไงให้ใช้ได้จริง:** หยิบมา **2-3 สัญญาณที่เด่นที่สุด** พอ (ไม่ใช่ไล่ทุกข้อ) ·
อ้างชื่อ + ตัวเลขของแถวจริงเสมอ · ปิดท้ายด้วย **คำถามชวนเจาะต่อ 1 ข้อ** ที่ตอบได้จากข้อมูลชุดเดิม

## หลังแสดงผล — อยู่ต่อเพื่อตอบคำถาม

หลังพิมพ์ตารางแล้ว **เขียนสรุปสั้น ๆ 2-4 บรรทัด** โดยใช้สัญญาณจาก
[§ อ่านผลยังไง](#-อ่านผลยังไง--สัญญาณของหัวข้อนี้) ข้างบน แล้วบอกว่าถามต่อได้
— **อย่าเทข้อมูลดิบซ้ำลงในแชท** · **ห้ามพิมพ์สรุปโดยไม่ได้อ่าน § อ่านผลยังไง ก่อน**

ตอบคำถามต่อจาก **ข้อมูลชุดเดิมที่ดึงมาแล้ว** ห้ามยิง tool ซ้ำ เว้นแต่:

| user ขอ | ทำอะไร |
|---|---|
| ตัวเลข/เจาะแถว/ตารางเต็ม/ระดับ ad set หรือแคมเปญ | ตอบจากข้อมูลเดิม **ไม่ต้องยิงใหม่** (ทั้ง 3 ระดับมาในก้อนเดียวกันอยู่แล้ว) |
| เปลี่ยนช่วงเวลา / เปลี่ยนเมตริก | ยิงใหม่ (จำช่วงเวลาเดิมไว้ ไม่ต้องถามซ้ำ) |
| "ทำไมตัวนี้อยู่ถัง Close" | อธิบายจากตัวเลขในแถวนั้น **แต่ย้ำว่าถังเป็นของปลายทาง เราไม่ได้ตัดสินเอง** |
| "ปิดตัวนี้ให้หน่อย" | **สกิลนี้ทำไม่ได้** — บอกตรง ๆ ว่าดูได้อย่างเดียว แล้วชี้ไป Ads Manager หรือสกิลจัดการงบ |

ขอตารางเต็ม = พิมพ์ทุกแถวเป็น markdown ในแชท · ถ้ายาวมากให้แบ่งตามระดับ
แล้วถามว่าจะดูระดับไหนก่อน

## ข้อควรระวังเรื่องตัวเลข

- **สตางค์/หน่วยเงิน**: ค่าที่ปลายทางส่งมาเป็นหน่วยเงินปกติแล้ว — ใช้ตามที่ได้มา ห้ามคูณ/หาร 100
- **`CTR` เป็นเปอร์เซ็นต์อยู่แล้ว** (เช่น `1.84` = 1.84%) → พิมพ์ต่อท้ายด้วย `%` **ห้ามคูณ 100 ซ้ำ**
- 🔴 **ต้นทุนต่อผล = `0` แปลว่า "ไม่มีผลลัพธ์" ไม่ใช่ "ถูก"** — แถวที่เมตริกหลัก = 0 ได้คอลัมน์ต้นทุนเป็น `0`
  → **ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่าตัวไหนถูกสุดเสมอ**
- **`ROAS` เป็นเท่า ไม่ใช่ %** → หัวคอลัมน์เขียนว่า "ROAS (เท่า)"
- `Impression` **ไม่มี s** · **ชื่อคอลัมน์อ่านจากแถวจริงเสมอ** (`Object.keys(rows[0])`) คีย์ไหนไม่มี = ตัดคอลัมน์ทิ้ง
- ชื่อคอลัมน์ชุดนี้ใช้ `Cost_per_Inbox` / `Cost_per_Lead` / `Cost_per_Purchase` (**`per` ตัวเล็ก**)
  — สะกดต่างจากสกิลตระกูล `maxxgpt-analysis-*` ที่ใช้ `Cost_Per_Inbox` **ห้ามจำสลับกัน**
- 🔴 **ถัง `Close` เต็มไปด้วยแถวที่ผลเป็น 0 → คอลัมน์ต้นทุนเป็น 0 ด้วย** — ห้ามอ่านว่า "ถูก"
  และห้ามเรียงถังนี้ด้วยต้นทุนจากน้อยไปมากโดยไม่ตัดแถวผล 0 ออกก่อน
- **ชุดนี้ไม่มี `Score`** — ภายในถังไม่ได้เรียงเป็นพิเศษ ถ้าจะเรียงให้เรียงเองตาม `Spend` แล้วบอกว่าเรียงด้วยอะไร
