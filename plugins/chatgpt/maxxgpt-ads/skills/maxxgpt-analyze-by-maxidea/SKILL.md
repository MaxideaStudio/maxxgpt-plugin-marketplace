# MaxxGPT — Analyze by MaxideaStudio (จัดอันดับโฆษณา)

พา user จาก "แอดตัวไหนดี ตัวไหนควรปิด" ไปจนได้ **รายการจัดอันดับจริง** ของบัญชีโฆษณาที่ผูกไว้กับ MaxxGPT
แล้วอยู่ต่อเพื่อตอบคำถามเจาะลึกจากข้อมูลชุดเดียวกัน

Rank the account's ads into keep / stop / scale sets, then stay to answer follow-ups.

> ## 🔴 กฎเหล็ก 6 ข้อ (อ่านก่อนเริ่มทุกครั้ง)
>
> 1. **เรียก MCP tool ทีละตัว ห้ามยิงขนาน** — ยิงพร้อมกันจะได้ error `The connector's server isn't
>    responding.` ที่**ดูเหมือน server พังทั้งที่ไม่ใช่** · เจอ error นี้ให้สงสัยวิธีเรียกของตัวเองก่อน
> 2. **ทุกหัวข้อเป็นงาน async** — ยิง tool ได้ `job_id` แล้วต้อง **poll `get_job` เองจนจบ** ตาม
>    `poll_hint.poll_after_seconds` · **ห้ามจบ turn คืนงานให้ user ระหว่างรอ**
> 3. **ห้ามเทข้อมูลดิบทั้งก้อนลงแชท** — คำนวณยอดรวมจากข้อมูลเต็ม แล้ว**พิมพ์ตารางแค่ 10 แถวต่อระดับ**
>    เสมอ (ดู § 5) · ข้อมูลเต็มยังอยู่กับเราไว้ตอบคำถามต่อ
> 4. **ตัวเลขทุกตัวต้องมาจาก `data` จริงเท่านั้น** — คีย์ไหนไม่มีก็ตัดคอลัมน์นั้นทิ้ง
>    **ห้ามเดา ห้ามเติมค่าที่ระบบไม่ได้ส่งมา ห้ามคำนวณเมตริกใหม่ที่ปลายทางไม่ได้ให้**
> 5. **การจัดกลุ่ม "ควรปิด / เฝ้าดู / ทำได้ดี" เป็นของปลายทาง ห้ามตัดสินเอง** — เราแสดงและอธิบาย
>    ตามถังที่ระบบจัดมา · **สกิลนี้ไม่ปิดโฆษณาให้ ไม่แก้งบให้** ได้แค่บอกว่าตัวไหนอยู่ถังไหน ·
>    🔴 **`bottom_rank` คือการคัดแยก *ทั้งบัญชี* ไม่ใช่ลิสต์ตัวที่แย่** — ถัง `Keep` คือตัวที่ทำได้ดี
>    **ห้ามเรียกทั้งชุดว่า "โฆษณาที่ทำได้แย่" และห้ามบอกว่าของในถัง Keep เป็นตัวไม่ดี**
> 6. **ห้ามสร้าง widget / ฟอร์ม HTML / การ์ด UI เด็ดขาด** — ห้ามเรียก tool แสดงวิชวลทุกตัว
>    (`visualize` · `show_widget` · `render-ui` · Artifact) และ**ห้ามเขียน HTML/ฟอร์มเอง**
>    ถามด้วย **tool `AskUserQuestion` (ปุ่มตัวเลือก)** เท่านั้น · เรียกไม่ได้จริง ๆ =
>    **ถามเป็นข้อความแบบเลขข้อ (1 / 2 / 3) แล้วหยุดรอ user ตอบ** ห้ามเดาเองแล้วยิงต่อ

## Connector ที่ต้องมี · Required connector

| Connector | URL | ใช้ทำอะไร |
|---|---|---|
| **MaxxGPT** | `https://mcp.maxxgpt.ai/mcp` | `get_account_info` · `analysis_good_*` / `analysis_bad_*` / `analysis_top_star` / `analysis_top_aware` · `get_job` |

> ### 🔁 เจอ connector ที่ชี้ไปโดเมนเก่า
> `https://mcp-beta.maxxgpt.ai/mcp` เป็น**โดเมนเดิม ใช้แก้ขัดได้** — เจอ connector ของ user ตั้งไว้แบบนั้น
> **ทำงานต่อได้ตามปกติ ห้ามหยุดงานเพื่อให้เขาไปเปลี่ยนก่อน** ·
> แต่ให้บอกหนึ่งบรรทัดตอนจบว่าโดเมนหลักคือ `https://mcp.maxxgpt.ai/mcp` และแนะนำให้ย้าย ·
> **บอกครั้งเดียวต่อ session พอ อย่าทวงซ้ำทุกรอบ**

ไม่มี connector นี้ = แจ้ง user พร้อม URL แล้วหยุด อย่าเดินหน้าด้วยการเดา ·
**ชื่อ tool ของแต่ละ user อาจไม่ตรงเป๊ะ** → จับคู่จาก *ความสามารถ* ไม่ใช่ชื่อเป๊ะ ๆ

> **บัญชีโฆษณา · เพจ (MaxxGPT V4)** — ไม่ส่งอะไร = tool ใช้บัญชี/เพจที่ user เลือกไว้ในเว็บ MaxxGPT (กรณีปกติ) ·
> ทุก tool รับ `ad_account_id` (`act_…`) และ `page_id` แบบ **optional** เพื่อรันกับบัญชี/เพจอื่นที่ user ผูกไว้ **เฉพาะครั้งนั้น** (ไม่เปลี่ยนค่าที่เลือกในเว็บ) ·
> id ต้องมาจาก `list_ad_accounts` / `list_pages` เท่านั้น — **ห้ามเดา** · ส่งตัวที่ไม่ได้ผูก = `AD_ACCOUNT_NOT_ALLOWED` / `PAGE_NOT_ALLOWED` (ไม่ fallback เงียบ) ·
> user มีหลายบัญชีแล้วไม่ระบุ → ใช้ค่า default ไปก่อน แล้วบอกชื่อบัญชีที่ใช้ในหัวรายงาน (ทุกคำตอบแนบ `ad_account {id,name,source}` — `source: requested` = มาจากที่ส่ง)
>
> **รหัสที่ต้องรู้จัก (V4):** `NO_AD_ACCOUNT` (428) = ยังไม่ต่อ Meta / ยังไม่เลือกบัญชี → ให้ user เปิดเว็บ MaxxGPT ต่อ Meta แล้วเลือกบัญชี ·
> `reason: OVER_QUOTA` = ผูกบัญชี/เพจเกินโควตาแพ็กเกจ (`ad_account_quota.linked > max_ad_accounts`) → ให้ไปกด "จัดการบัญชี" ในเว็บเลือกตัวที่จะเก็บก่อน **อย่า retry** ·
> `NOT_ENTITLED` (403) = แพ็กเกจไม่รวมฟีเจอร์นี้ · `JOB_RUNNING_FOR_OTHER_ACCOUNT` = งานชนิดเดียวกันกำลังรันให้อีกบัญชีของ user นี้ รอจบก่อน · `JOB_NOT_FOUND` = `job_id` ไม่ใช่ของ user นี้

## 🔀 สกิลนี้เป็น "ทางเข้ารวม" — รู้หัวข้อแล้วให้ส่งต่อ

แต่ละหัวข้อมี**สกิลของตัวเอง**แล้ว (เนื้อหาละเอียดกว่า มีกับดักเฉพาะหัวข้อครบกว่า) ·
สกิลนี้มีไว้สำหรับตอนที่ **ยังไม่รู้ว่า user อยากได้มุมไหน** เท่านั้น

| `topic` | สกิลรายหัวข้อที่ควรใช้แทน |
|---|---|
| `top_rank` | `maxxgpt-rank-top-ads` |
| `bottom_rank` | `maxxgpt-rank-bottom-ads` |
| `rising_stars` | `maxxgpt-rank-rising-stars` |
| `audience_growth` | `maxxgpt-rank-audience-growth` |

**กติกา:**

- **รู้หัวข้อตั้งแต่ต้น** (user บอกมา / เดาจากบริบทได้ชัด) → **เรียกสกิลรายหัวข้อไปเลย ไม่ต้องเปิดเมนูของสกิลนี้**
- **user เพิ่งเลือกหัวข้อจากเมนูของสกิลนี้** → ส่งต่อให้สกิลรายหัวข้อพร้อมเมตริก + ช่วงวันที่ + `spend` ที่ได้มา
  **ถ้าสกิลรายหัวข้อนั้นไม่ได้ติดตั้งอยู่ ให้ทำต่อเองในสกิลนี้ตามขั้น 2-5 ปกติ** (ยังทำได้ครบ)
- ทั้งสองทางให้ผลเหมือนกัน — **ห้ามทำสองรอบ ห้ามยิง tool ซ้ำ**

## ⚡ ทางลัด · มี `job_id` มาแล้ว = ข้ามไปวิเคราะห์เลย

**ถ้าข้อความของ user มี `job_id` ติดมา ให้ข้ามขั้น 1-2 ทั้งหมด** — ไม่ต้องถามอะไรเพิ่มเลือกหัวข้อ/เมตริก
**ไม่ต้องยิง tool จัดอันดับใหม่** (ยิงใหม่ = เสียเวลา 1-5 นาที + เปลืองโควตา + อาจชน `JOB_ALREADY_RUNNING`)

**นับว่า "มี job_id" เมื่อ:** user พิมพ์/วางมาตรง ๆ (`job_id=…` · `[job_id=…]` · "ดูผลจากจ็อบ …" ·
วาง id ดิบ ๆ มาพร้อมบอกให้วิเคราะห์) · สกิลอื่นหรือเทิร์นก่อนหน้าส่งต่อมาให้ · งานตั้งเวลา/ระบบภายนอกแนบมา

```
job_id ที่ได้มา ──► get_job(job_id) ──► poll จน success ──► เช็คลายเซ็นว่าเป็นหัวข้อไหน ──► ตัด+แสดงผล
```

### ทำตามนี้

1. **`get_job(job_id)` ทันที** — `processing` ก็ poll ต่อตามขั้น 3 ปกติ
2. **`get_account_info`** ยังต้องเรียก (1 ครั้งต่อ session) เพื่อเอา **สกุลเงิน + ชื่อบัญชี** ไปใส่หัวเรื่อง
3. **หาว่าเป็นหัวข้อไหนจากรูปร่างของ `data`** (ดูตารางข้างล่าง) แล้วใช้กติกาตาราง/คอลัมน์/สรุปของหัวข้อนั้นใน § 5
   → เป็น 1 ใน 4 หัวข้อของสกิลนี้ = เดินต่อขั้น 4-5 ปกติ **บอก user ด้วยว่าอ่านได้ว่าเป็นหัวข้ออะไร**
   → **เป็นของสกิลอื่น** = ห้ามฝืนแปลง บอก user แล้วชี้สกิลที่ตรง
4. **`metric` ก็ไม่ได้ติดมาเหมือนกัน** — เดาจาก**คอลัมน์ผลที่โผล่ในแถว**: `Inbox`+`Cost_per_Inbox` = `inbox` ·
   `Lead`+`Cost_per_Lead` = `lead` · `Purchase`+`Cost_per_Purchase` = `purchase` ·
   `Purchase_Value`+`ROAS` (ไม่มีคอลัมน์ต้นทุน) = `roas` · **เขียนกำกับในหัวเรื่องว่าอ่านได้ว่าวัดด้วยอะไร**
5. **ช่วงวันที่: `get_job` ไม่ได้คืนมาด้วย** — 🔴 **ห้ามเดา ห้ามใส่ช่วงมั่ว ๆ ในหัวเรื่อง**
   · user บอกช่วงมาด้วย = ใช้ตามนั้น · ไม่บอก = เว้นช่วงวันที่ในหัวเรื่องไว้ แล้วเขียนในหมายเหตุว่า
   "ผลชุดนี้มาจาก job ที่ส่งมา — ระบบไม่ได้แนบช่วงวันที่มาด้วย"
6. `code: JOB_NOT_FOUND` = **job_id ผิด หรือเป็นของ user คนอื่น** (job ผูกกับ login) →
   บอกตรง ๆ แล้วเสนอรันใหม่ตามขั้น 1-2 ปกติ · **ห้าม poll ซ้ำ** (`poll_hint.poll_after_seconds` = 0)
7. `job_status: failed` = งานเก่าตายไปแล้ว → เสนอรันใหม่ · `data` ว่าง `{}` = ช่วงนั้นไม่มีข้อมูล ไม่ใช่ error

### ตารางลายเซ็น — job_id นี้เป็นของหัวข้อไหน

| ลายเซ็นใน `data` | หัวข้อ | สกิลที่ควรใช้ |
|---|---|---|
| `Ad` เป็น **object** `{Close,Watch,Keep}` | Bottom Rank | `maxxgpt-rank-bottom-ads` |
| แถวมี `Score` + `CPC` · **ไม่มี `CPM`** และไม่มีคอลัมน์ผลลัพธ์ | Rising Stars | `maxxgpt-rank-rising-stars` |
| แถวมี `Score` + `Reach` + `Frequency` + `CPM` + `CPC` | Audience Growth | `maxxgpt-rank-audience-growth` |
| แถวมี `Score` + `CPM` + `Cost_per_*` (`per` ตัวเล็ก) · ไม่มี `Reach`/`CPC` | Top Rank | `maxxgpt-rank-top-ads` |
| แถวมี `Video_plays` + `Completion_Rate` | โฆษณาวิดีโอ | `maxxgpt-analysis-video-ads` |
| แถวมี `Post_Engagement` + `post_engagement_rate` | เอนเกจโพสต์ | `maxxgpt-analysis-post-engagement` |
| แถวมี `Inbox` + `MSS_VIEW` + `Cost_Per_Inbox` (`Per` ตัวใหญ่) | ทักแชท | `maxxgpt-analysis-message` |
| แถวมี `Lead` + `Cost_per_lead` | ลีด | `maxxgpt-analysis-leads` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **และ** มีคีย์ `Age`/`Gender` | ยอดซื้อ Meta | `maxxgpt-analysis-purchase-meta` |
| แถวมี `Purchase`/`Purchase_Value`/`ROAS` **แต่ไม่มี** คีย์ `Age`/`Gender` | ยอดซื้อ CPAS | `maxxgpt-analysis-purchase-cpas` |
| `data` มีคีย์ `OV` | Ad Metric Benchmark (สเต็ป 1) | `maxxgpt-ad-metric-benchmark` |
| `data` มีบล็อก `CTR`/`CPM`/`FRQ` + `*_AD` | Ad Metric Benchmark (สเต็ป 2) | `maxxgpt-ad-metric-benchmark` |

⚠️ `purchase_meta` กับ `purchase_cpas` คอลัมน์เหมือนกันเป๊ะ แยกได้แค่จากคีย์ `Age`/`Gender` —
**ถ้าไม่มั่นใจให้บอก user ตรง ๆ ว่าเดาว่าเป็นหัวข้อไหน แล้วให้ยืนยัน** อย่าเงียบแล้วเดา

## ผังการทำงาน · Flow

```
0  get_account_info ──► รู้ชื่อบัญชี + สกุลเงิน + โซนเวลา
1  ถามเลือกหัวข้อ + ตัวเลือกย่อย + ช่วงเวลา ด้วย AskUserQuestion  ◄── ข้ามได้ถ้า user บอกมาแล้ว
2  ยิง tool ตามตาราง § 2                                    ──► { job_id, code }
3  วนเรียก get_job จนกว่า job_status = success               ◄── ตาม poll_hint ห้ามจบ turn
4  ตัดข้อมูล + คำนวณยอดรวม
5  พิมพ์สรุป + ตาราง markdown             ──►  อยู่ต่อเพื่อตอบคำถามจากข้อมูลชุดเดิม
```

### ขั้น 0 · รู้ก่อนว่าบัญชีไหน

เรียก `get_account_info` **หนึ่งครั้งต่อ session** เก็บ ชื่อบัญชี / `act_…` / สกุลเงิน / โซนเวลา ไว้ใช้ทุกขั้น

tool คืน `{ success, ad_account, page }` — ที่ต้องหยิบไปใช้:

| คีย์ใน `ad_account` | เอาไปใช้ตรงไหน | หมายเหตุ |
|---|---|---|
| `name` | ชื่อบัญชีในหัวเรื่อง | ชื่อบัญชีโฆษณา |
| `id` | วงเล็บต่อท้ายชื่อบัญชี | มี prefix `act_` มาแล้ว (`account_id` คือตัวไม่มี prefix) |
| `currency` | หน่วยเงินต่อท้ายตัวเลขเงินในตาราง | เช่น `THB` — `null` ได้ |
| `timezone_name` | ใช้คำนวณ "วันนี้" ตอนแปลงช่วงเวลา | เช่น `Asia/Bangkok` |
| `account_status` | เตือนไว้ในหมายเหตุถ้าบัญชีมีปัญหา | **เป็นตัวเลข ไม่ใช่ข้อความ** — `1` = ใช้งานได้ · ค่าอื่น (`2`,`3`,`101`,…) = บัญชีมีปัญหา |

- โซนเวลาใช้คำนวณ **"วันนี้"** ตอนแปลงคำพูดเป็นช่วงวันที่ — หาไม่เจอให้ใช้ `Asia/Bangkok`
- สกุลเงินใช้ต่อท้ายตัวเลขเงินทุกตัว — หาไม่เจอให้เว้นว่าง **ห้ามเดาว่าเป็น THB**

### ขั้น 1 · เลือกหัวข้อ + ตัวเลือกย่อย + ช่วงเวลา

**ถ้า user บอกมาครบแล้ว ไม่ต้องถามอะไรอีก** — บอกหนึ่งบรรทัดว่าใช้อะไร แล้วยิงต่อ

| user พูดมาแบบ | ทำอะไร |
|---|---|
| บอกครบ ("แอดแชทตัวไหนดีเดือนที่แล้ว") | ไม่ต้องถาม → ยิงเลย + บอกว่าใช้หัวข้อ/เมตริก/ช่วงไหน |
| บอกหัวข้อแต่ไม่บอกเมตริก ("ตัวไหนควรปิด") | **ถ้าเดาเมตริกจากบริบทได้ให้เดา** (พูดถึงแชท = `inbox`, ลีด = `lead`, ยอดขาย = `purchase`) แล้วบอกว่าเลือกให้ · เดาไม่ได้ = ถามเฉพาะเมตริก (หัวข้อรู้แล้ว) |
| บอกแต่หัวข้อ + **เคยรู้ช่วงเวลาแล้วใน session นี้** | ใช้ช่วงเดิมต่อ ยิงเลย + บอกว่าใช้ช่วงเดิม |
| ไม่บอกอะไรเลย | ถามหัวข้อ + เมตริก + ช่วงเวลาด้วย `AskUserQuestion` ครั้งเดียว |

**ห้ามถามช่วงเวลาซ้ำ** ถ้า session นี้เคยได้ช่วงเวลามาแล้ว (รวมถึงช่วงที่ได้มาจากสกิลวิเคราะห์ตัวอื่น)
— ใช้ค่าเดิมต่อ แล้วบอกว่ากำลังใช้ช่วงไหน · user เปลี่ยนทีหลังได้โดยบอกมาในแชท (ไม่ต้องถามใหม่ด้วยปุ่ม)

**ถามยังไง — ใช้ tool `AskUserQuestion` (ปุ่มตัวเลือก) เสมอ · ห้ามสร้าง widget/ฟอร์ม HTML · ห้ามพิมพ์คำถามเปล่า ๆ:**
สเปกคำถาม/ตัวเลือกอยู่ใน [references/output-format.md](references/output-format.md) § ถาม — เมนู 4 หัวข้อ + เมตริก + ช่วงเวลา
**ถามทุกอย่างที่ยังไม่รู้ในการเรียกครั้งเดียว** (สูงสุด 4 คำถาม/ครั้ง) · ที่รู้แล้วห้ามถามซ้ำ

### ขั้น 2 · ยิง tool

| `topic` | `metric` | tool | พารามิเตอร์ |
|---|---|---|---|
| `top_rank` | `inbox` | `analysis_good_inbox` | `date_start`, `date_end`, `spend` |
| `top_rank` | `lead` | `analysis_good_lead` | `date_start`, `date_end`, `spend` |
| `top_rank` | `purchase` | `analysis_good_purchase` | `date_start`, `date_end`, `spend` |
| `top_rank` | `roas` | `analysis_good_roas` | `date_start`, `date_end`, `spend` |
| `bottom_rank` | `inbox` | `analysis_bad_inbox` | `date_start`, `date_end`, `spend` |
| `bottom_rank` | `lead` | `analysis_bad_lead` | `date_start`, `date_end`, `spend` |
| `bottom_rank` | `purchase` | `analysis_bad_purchase` | `date_start`, `date_end`, `spend` |
| `rising_stars` | — | `analysis_top_star` | `date_start`, `date_end`, **`spend`** |
| `audience_growth` | — | `analysis_top_aware` | `date_start`, `date_end`, **`spend`** |

- `spend` = **ยอดใช้จ่ายขั้นต่ำที่จะเอามาจัดอันดับ** (ตัดแถวเล็ก ๆ ที่เป็น noise ออก) · ค่าเริ่มต้น `0` =
  เอาทุกแถว · เป็นตัวเลข ไม่ใช่สตริง · **ใช้ได้ทุกหัวข้อแล้ว** — เป็นตัวกรองหลักของ
  `rising_stars`/`audience_growth` และตัวกรองเสริมของ `top_rank`/`bottom_rank` · user ไม่ได้ระบุ =
  ส่ง `0` (ไม่กรอง)
- `bottom_rank` **ไม่มี** `metric=roas` (ปลายทางไม่มี) — user ขอมาให้บอกตรง ๆ แล้วเสนอ `purchase` แทน

ผลที่ได้คือ `{ job_id, code }` — **`code` มี 2 แบบที่ต้องแยก:**

| `code` | หมายถึง | ทำอะไรต่อ |
|---|---|---|
| `JOB_CREATED` | เริ่มงานใหม่แล้ว | poll ตามปกติ |
| `JOB_ALREADY_RUNNING` | **มีงานหัวข้อเดียวกันค้างอยู่ — `job_id` ที่ได้เป็นของงานเก่า** | poll ต่อได้ แต่ **ผลเป็นของช่วงวัน/เมตริกที่สั่งไว้รอบก่อน** → บอก user ตรง ๆ + เขียนไว้ในหมายเหตุ แล้วเสนอรันใหม่หลังงานเก่าจบ |

> 1 user มีงานของ **tool เดียวกัน** ได้ทีละ 1 งาน — `analysis_good_inbox` กับ `analysis_good_lead`
> ถือเป็นคนละงาน แต่เรายังยิงทีละตัวอยู่ดี

### ขั้น 3 · รอผล (poll)

```
get_job(job_id)  →  { job_status, progression, data, poll_hint }
```

- `processing` → รอ `poll_hint.poll_after_seconds` วินาที **พิมพ์บรรทัดสั้น ๆ ให้ user เห็นว่ายังทำงานอยู่**
  แล้ว poll ต่อ **ห้ามจบ turn**
- `success` → อ่าน `data` · **`data` อาจมาเป็นสตริง JSON → parse ก่อนใช้**
- `failed` + `data = {"error":"time_out"}` → เกินเพดาน 5 นาที **ห้ามยิงซ้ำทันที**: บอก user ว่าช่วงที่ขอหนักไป
  เสนอย่นช่วงวัน หรือ poll ต่ออีกสักครู่ (งานเบื้องหลังอาจยังวิ่งและพลิกเป็น `success` เองได้)
- `poll_hint.poll_after_seconds = 0` = หยุด อย่า poll ต่อ
- error อื่น: `401` = token เว็บ MaxxGPT ใช้ไม่ได้/แพ็กเกจหมดอายุ → ให้ล็อกอินเว็บใหม่ · `403` = แพ็กเกจไม่ครอบคลุม
  · `422` = ช่วงวันผิดรูป · `424` = ปลายทางมีปัญหา ลองใหม่ภายหลัง

แล้วพิมพ์เป็นข้อความ + ตาราง markdown ตาม [references/output-format.md](references/output-format.md) § ตอบ

## § 5 · กติกาตัดข้อมูล + วางตาราง (ห้ามข้าม)

### ตาราง — ต่างกันตามกลุ่มหัวข้อ

| หัวข้อ | ตารางที่ต้องพิมพ์ |
|---|---|
| `top_rank` · `rising_stars` · `audience_growth` | **แคมเปญ / Ad set / โฆษณา** (เรียงมาให้แล้วตาม `Score`) |
| `bottom_rank` | **🔴 ควรปิด (Close) / 🟡 เฝ้าดู (Watch) / 🟢 ทำได้ดี ปล่อยวิ่งต่อ (Keep)** — ใช้ **ระดับโฆษณา (`Ad`)** เพราะเป็นระดับที่ลงมือได้จริง · เขียนใต้ตารางว่า "ระดับ ad set / แคมเปญ ขอดูได้โดยพิมพ์บอก" |

- แต่ละตารางเอา **10 แถวแรก** · ถ้าตัดออก เขียนใต้ตารางว่า "แสดง 10 จากทั้งหมด N"
- **`Score` เรียงมาให้แล้ว — พิมพ์ตามลำดับเดิม อย่าเรียงใหม่** · `Score` ชุดนี้เป็น **0-100**
- 🔴 **`Score` คิดจาก CPM + CTR ไม่ได้คิดจากเมตริกที่ user เลือก** → อันดับ 1 อาจมีค่าเมตริกต่ำกว่าอันดับ 3 ได้
  (ของจริงเจอ ad set ROAS 5.62 ได้ Score 100 ส่วน ROAS 16.87 ได้ Score 0) · **ต้องเขียนไว้ในหัวเรื่อง
  ว่า "เรียงตามคุณภาพการส่ง (CPM+CTR) ไม่ใช่ตามค่าเมตริก"** ไม่งั้น user คิดว่าระบบคำนวณผิด ·
  user อยากได้อันดับตามเมตริกตรง ๆ = เรียงใหม่ให้ได้ แต่ต้องบอกว่าเปลี่ยนวิธีเรียงแล้ว
- คอลัมน์ 4-6 คอลัมน์พอ: ชื่อ · `Spend` · คอลัมน์ผลของ metric · คอลัมน์ต้นทุนของ metric · `CTR`
  (ดูตารางจับคู่ metric ↔ คอลัมน์ใน [output-shape.md](references/output-shape.md))
- `top_rank` ใส่คอลัมน์ `Score` ท้ายตารางด้วย (เป็นเหตุผลของอันดับ)
- `rising_stars` ใช้คอลัมน์: ชื่อ · `Spend` · `Impression` · `CTR` · `CPC` · `Score` — **ไม่มี `CPM`
  และไม่มีคอลัมน์ผลลัพธ์ใด ๆ ในชุดนี้** อย่าไปหา
- `audience_growth` ใช้คอลัมน์: ชื่อ · `Spend` · `Reach` · `Frequency` · `CPM` · `CTR` · `Score`
- ระดับโฆษณา ให้ทำชื่อเป็นลิงก์ markdown ไปที่ `post_url` เสมอ (`[ชื่อ](post_url)`)
- **ชื่อซ้ำกันได้จริง** (แคมเปญคนละ id ชื่อเดียวกัน · ad set ชื่อ `M-W` หลายตัว · โฆษณาชื่อ `-`) →
  ตารางระดับ ad set/โฆษณา **ต้องมีคอลัมน์แคมเปญกำกับ** และตอบคำถามรายตัวให้แนบ id
- **ไม่มี ตาราง breakdown** ในสกิลนี้ (ชุดนี้ไม่มี breakdown อายุ/เพศ/อุปกรณ์) — ถ้า user อยากได้ ให้บอกว่าอยู่ในสกิล
  วิเคราะห์ผลโฆษณา (performance analysis)

### สรุปรวม 4 ช่อง (พิมพ์เป็นตารางเดียว)

| หัวข้อ | ช่อง 1 | ช่อง 2 | ช่อง 3 | ช่อง 4 |
|---|---|---|---|---|
| `top_rank` | จำนวนโฆษณาที่เข้าเกณฑ์ | ยอดใช้จ่ายรวมของกลุ่มนี้ | ผลรวมของ metric | ต้นทุนต่อผลรวม (หรือ ROAS) |
| `bottom_rank` | 🔴 ควรปิด (กี่ตัว) | 🟡 เฝ้าดู (กี่ตัว) | 🟢 ทำได้ดี (กี่ตัว) | ยอดใช้จ่ายที่จมอยู่กับกลุ่ม "ควรปิด" |
| `rising_stars` | จำนวนที่เจอ | ยอดใช้จ่ายรวม | CTR สูงสุดที่เจอ | ยอดแสดงผลรวม |
| `audience_growth` | จำนวนที่เจอ | ยอดใช้จ่ายรวม | CPM ต่ำสุดที่เจอ | ความถี่เฉลี่ย |

**ยอดรวมคำนวณยังไงถึงจะถูก:**

- รวมจากแถวระดับ **Campaign** (ไม่ใช่ Ad เพื่อไม่ให้นับซ้ำ) เว้นแต่ชุดนั้นมีแต่ระดับ Ad
- **ต้นทุนต่อผลรวม = `Spend รวม ÷ ผลรวม`** — **ห้ามเอาต้นทุนรายแถวมาเฉลี่ย** (ได้เลขผิด)
- `CTR รวม` = `Clicks รวม × 100 ÷ Impression รวม` ไม่ใช่ค่าเฉลี่ยของ `CTR` รายแถว
- `bottom_rank` นับจำนวนจาก **ระดับโฆษณา** ของแต่ละถัง

### บรรทัดชวนถามต่อ (พิมพ์ปิดท้ายเสมอ)

```
ถามต่อได้: ขอตารางเต็มทุกแถว · เลือกหัวข้ออื่น · เปลี่ยนช่วงเวลา
```

`bottom_rank` เพิ่มอีกข้อ: "ดูระดับ ad set / แคมเปญ"

### หมายเหตุ และผลว่าง

**หมายเหตุ (bullet `⚠️` ใต้ตาราง) ใส่เมื่อ:** ช่วงที่ขอรวมวันนี้ · ผลว่าง · ผลมาจาก job เก่า (`JOB_ALREADY_RUNNING`) ·
บัญชีไม่ ACTIVE · ใช้ `spend` กรอง (บอกว่ากรองที่เท่าไร ไม่งั้น user งงว่าทำไมแอดหาย)

**ผลว่าง (`data` = `{}` หรือทุกถังว่าง):** ยัง พิมพ์ตารางตามปกติ แต่ `note` บอกเหตุผลแบบภาษาคน
แล้วเสนอทางแก้ที่ตรงกับหัวข้อ:

| หัวข้อ | ข้อความที่ควรบอก |
|---|---|
| `top_rank` | "ช่วงนี้ไม่มีโฆษณาตัวไหนผ่านเกณฑ์ 'ทำได้ดี' ของเมตริกนี้" → ลองเมตริกอื่น / ช่วงยาวขึ้น · **ถ้าตั้ง `spend` ไว้ให้ลองลดลงก่อน** |
| `bottom_rank` | ถ้า `Close` ว่างแต่ถังอื่นมีของ = **ข่าวดี ไม่ใช่ error** ("ไม่มีตัวที่เข้าข่ายควรปิด") · ว่างทั้ง 3 ถัง = ช่วงนี้ไม่มีโฆษณาที่มีข้อมูลเลย (ถ้าตั้ง `spend` ไว้ ลองลดลงด้วย) |
| `rising_stars` · `audience_growth` | ถ้าใส่ `spend` ไว้สูง ให้เสนอลดลงก่อนเป็นอย่างแรก |

## หลังแสดงผล — อยู่ต่อเพื่อตอบคำถาม

หลังพิมพ์ตารางแล้ว **เขียนสรุปสั้น ๆ 2-4 บรรทัด** แล้วบอกว่าถามต่อได้ — **อย่าเทข้อมูลดิบซ้ำลงในแชท**

ตอบคำถามต่อจาก **ข้อมูลชุดเดิมที่ดึงมาแล้ว** ห้ามยิง tool ซ้ำ เว้นแต่:

| user ขอ | ทำอะไร |
|---|---|
| ตัวเลข/อันดับ/เจาะแถว/ตารางเต็ม/ระดับอื่น | ตอบจากข้อมูลเดิม **ไม่ต้องยิงใหม่** |
| เปลี่ยนช่วงเวลา / เปลี่ยนเมตริก / เปลี่ยนหัวข้อ | ยิงใหม่ (จำช่วงเวลาเดิมไว้ ไม่ต้องถามซ้ำ) |
| "ปิดตัวนี้ให้หน่อย" / "เพิ่มงบตัวนี้" | **สกิลนี้ทำไม่ได้** — บอกตรง ๆ ว่าดูได้อย่างเดียว แล้วชี้ว่าต้องไปทำใน Ads Manager หรือใช้สกิลจัดการงบ |
| อยากดู breakdown อายุ/เพศ/อุปกรณ์ | ไม่มีในชุดนี้ — ชี้ไปที่สกิลวิเคราะห์ผลโฆษณา (performance analysis) |

ขอตารางเต็ม = พิมพ์ทุกแถวเป็น markdown ในแชท

## ข้อควรระวังเรื่องตัวเลข

- **สตางค์/หน่วยเงิน**: ค่าที่ได้เป็นหน่วยเงินปกติแล้ว — ใช้ตามที่ได้มา ห้ามคูณ/หาร 100
- **`CTR` เป็นเปอร์เซ็นต์อยู่แล้ว** (เช่น `1.84` = 1.84%) → พิมพ์ต่อท้ายด้วย `%` **ห้ามคูณ 100 ซ้ำ**
- **`ROAS` เป็นเท่า ไม่ใช่ %** → หัวคอลัมน์เขียนว่า "ROAS (เท่า)"
- **`Frequency` เป็นจำนวนครั้งเฉลี่ยต่อคน** ไม่ใช่ % → พิมพ์เป็นตัวเลข (ใส่ลูกน้ำ)
- 🔴 **ต้นทุนต่อผล = `0` แปลว่า "ไม่มีผลลัพธ์" ไม่ใช่ "ถูก"** — แถวที่เมตริกหลัก = 0 ได้ `Cost_per_*` เป็น `0`
  → **ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่าตัวไหนถูกสุดเสมอ** (สำคัญมากกับ `bottom_rank`
  ที่เต็มไปด้วยแถวผล 0)
- ชื่อคอลัมน์ชุดนี้ใช้ `Cost_per_Inbox` / `Cost_per_Lead` / `Cost_per_Purchase` (**`per` ตัวเล็ก**)
  — สะกดต่างจากชุด performance analysis **ห้ามจำสลับกัน**
