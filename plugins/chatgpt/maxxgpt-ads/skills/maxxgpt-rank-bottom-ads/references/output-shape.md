# หน้าตาข้อมูลที่ได้จาก `get_job`

อ่านไฟล์นี้ตอนจะแปลงผลเป็นตาราง เพื่อรู้ว่าจะหยิบคีย์ไหน

> ## 🔑 กฎเดียวที่ห้ามข้าม
> **อ่านชื่อคีย์จากแถวจริงเสมอ** (`Object.keys(rows[0])`) แล้วค่อยเลือกคอลัมน์ตามตารางข้างล่าง ·
> ตารางนี้คือ *สิ่งที่คาดว่าจะเจอ* ไม่ใช่สัญญาตายตัว — ปลายทางเป็น flow ของเว็บ MaxxGPT
> ที่แก้ไขได้โดยไม่ผ่านสกิลนี้ · **คีย์ไหนไม่มี = ข้ามคอลัมน์นั้นไป ห้ามเดาค่า ห้ามคำนวณแทน**

`data` จาก `get_job` อาจมาเป็น **สตริง JSON → ต้อง parse ก่อน** · `{}` ว่าง = ไม่มีแถวเข้าเกณฑ์ (ไม่ใช่ error)

## รูปแบบรวม — หัวข้อ `bottom_rank` (`analysis_bad_<metric>`)

```
{ "Ad":      {"Close":[…], "Watch":[…], "Keep":[…]},
  "Adset":   {"Close":[…], "Watch":[…], "Keep":[…]},
  "Campaign":{"Close":[…], "Watch":[…], "Keep":[…]} }
```

> ## 🔴 ชุดนี้ไม่ได้คืนแค่ "ตัวที่แย่" — มันคือ **การคัดแยกทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก**
> โฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดนั้นและมี `Spend` > 0 (และถึง `spend` ที่กรอง) จะถูกจัดลงถังใดถังหนึ่ง **รวมตัวที่ทำได้ดีที่สุดด้วย** ·
> โฆษณาที่ตั้งเป้าเป็นผลลัพธ์อื่นไม่อยู่ในถังใดเลย · มีแถวที่ได้ผลลัพธ์ไม่ถึง 4 แถว = ไม่มีถัง `Keep` (ผล 0 = `Close` · ที่เหลือ = `Watch`)

| ถัง | ความหมายที่ต้องสื่อให้ user | หัวข้อแท็บที่ใช้ |
|---|---|---|
| `Keep` | **ทำได้ดี ปล่อยวิ่งต่อ** — ถังนี้คือตัวที่ควรเก็บไว้ (ของจริงเจอตัวที่ต้นทุน/แชทถูกที่สุดของบัญชีอยู่ในนี้) | 🟢 ทำได้ดี ปล่อยวิ่งต่อ (Keep) |
| `Watch` | ก้ำกึ่ง — **เฝ้าดูต่อ** ยังไม่ต้องรีบปิด | 🟡 เฝ้าดูต่อ (Watch) |
| `Close` | แย่ชัดเจน — **ควรปิด** | 🔴 ควรปิด (Close) |

⚠️ **ห้ามเรียกทั้งชุดนี้ว่า "โฆษณาที่ทำได้แย่"** และ **ห้ามบอกว่าของในถัง `Keep` เป็นตัวไม่ดี** —
พูดให้ตรงว่า "คัดแยกโฆษณาที่ตั้งเป้าผลลัพธ์นี้เป็น 3 กลุ่ม: เก็บไว้ / เฝ้าดู / ควรปิด"

⚠️ **ห้ามสรุปเองว่าให้ปิดตัวไหน** — ถังที่ปลายทางจัดมาให้แล้วคือคำตอบ หน้าที่เราคือแสดงและอธิบาย

## ⚡ เช็คก่อนว่า job นี้เป็นของหัวข้อนี้จริงไหม

ใช้ตอนที่ user ส่ง `job_id` มาให้ตรง ๆ — `get_job` คืน **`function_name`** บอกว่า job มาจากหัวข้อไหน
ให้ดูค่านั้นก่อน · รูปร่างของ `data` ใช้เป็นทางสำรองเมื่อไม่มี `function_name`

👉 **ตารางลายเซ็นเต็ม (ทุกหัวข้อ + สกิลที่ควรใช้) อยู่ใน [SKILL.md](../SKILL.md) § ทางลัด** — อ่านที่นั่นที่เดียว
เพื่อไม่ให้สองที่ขัดกัน

## คอลัมน์ของแถว

**ปลายทางตัดคอลัมน์มาให้แล้ว — ได้มาน้อยกว่าที่คิด** คอลัมน์ฐาน:
`<level>_id` · `<level>_name` · `Spend` · `Impression` · `Clicks` · `CTR` · ระดับ Ad มี `post_url` (ว่างได้)

| | |
|---|---|
| คอลัมน์ที่เพิ่มมา | `CPM` · `Purchase` · คอลัมน์ผล + ต้นทุนของ metric · **ไม่มี `Score`** |
| เรียงมาให้แล้วตาม | — (ภายในถังไม่ได้เรียงเป็นพิเศษ) |

⚠️ **`Objective` / `Result` / `Result_indicator` / `MSS_VIEW` / `Purchase_meta` / `Purchase_CPAS`
ไม่ได้ติดมา** ในผลลัพธ์ของชุดนี้ (มีอยู่แค่ภายใน flow) — อยากได้ต้องไปที่ `maxxgpt-export-report`

## คอลัมน์ต้นทุนต่อผลที่คู่กับ metric แต่ละตัว

| `metric` | คอลัมน์ผล | คอลัมน์ต้นทุน |
|---|---|---|
| `inbox` | `Inbox` | `Cost_per_Inbox` |
| `lead` | `Lead` | `Cost_per_Lead` |
| `purchase` | `Purchase` | `Cost_per_Purchase` |

⚠️ ชุดนี้ใช้ `Cost_per_*` (**`per` ตัวเล็ก**) ซึ่ง **ต่างจากสกิล `maxxgpt-analysis-message`
ที่ใช้ `Cost_Per_Inbox` (`Per` ตัวใหญ่)** และต่างจาก `maxxgpt-analysis-leads` ที่ใช้ `Cost_per_lead`
(`lead` ตัวเล็ก) — **อ่านจากแถวจริงเสมอ**

## ชุดนี้ **ไม่มี `Score`**

ถังที่จัดมาให้คือคำตอบ ไม่มีคะแนนกำกับ — ถ้าจะเรียงในตารางให้เรียงเองตาม `Spend` แล้ว**บอกว่าเรียงด้วยอะไร**

### 🔴 กับดักที่ทำให้อันดับผิด: ต้นทุนต่อผล = `0` เมื่อไม่มีผลลัพธ์

แถวที่เมตริกหลัก = 0 จะได้คอลัมน์ต้นทุนเป็น **`0` ไม่ใช่ `null`** → เรียง "ถูกสุด" จากน้อยไปมากตรง ๆ
แล้ว **แถวที่ไม่ได้ผลอะไรเลยจะขึ้นอันดับ 1**

**กติกา:** ตัดแถวที่เมตริกหลัก = 0 ออกก่อนเรียง/ก่อนสรุปว่า "ตัวไหนถูกสุด" เสมอ · **สำคัญมากกับถัง `Close` ที่เต็มไปด้วยแถวผล 0**

### ⚠️ ชื่อซ้ำกันได้ ต้องมี id กำกับ

ของจริงเจอ **แคมเปญ 2 ตัวชื่อเดียวกันเป๊ะ** (คนละ `campaign_id`) และชื่อ ad set ซ้ำข้ามแคมเปญ
(`M-W`, `New Engagement Ad Set`) · ชื่อโฆษณาก็ซ้ำ (`-`, `รูป`, `video`) →
**ตารางระดับ ad set / โฆษณา ให้กำกับด้วย id ของแถวนั้น** (แถวไม่มีชื่อ/ID แคมเปญติดมา) และถ้า user ถามถึงตัวใดตัวหนึ่งให้ตอบพร้อม id

## tool คืนมาเท่าไร

**ทุกโฆษณาที่ตั้งเป้าเป็นผลลัพธ์ชนิดที่เลือก** แยก 3 ถัง (ของจริง 42 ads รวมทุกถัง)

## จำนวนแถวที่ต้องคาด

ชุดนี้ปลายทางกรองมาให้แล้ว จึงสั้นกว่ารายงาน `maxxgpt-analysis-*` มาก แต่บัญชีใหญ่ก็ยังมีได้หลายสิบแถว
→ ยังต้องตัดเหลือ 10 แถวก่อนพิมพ์ตาราง ตามกฎใน SKILL.md § 5
